# 트러블슈팅 기록

MOLLI 를 만들면서 부딪힌 문제와 원인, 고친 방법을 날짜순으로 적었습니다. 날짜와 순서는 한국 시간 기준입니다.

항목마다 **증상 → 원인 → 해결** 순서입니다. 뱀서 관련 수정은 대부분 **가짜 화면·가짜 LLM 으로만 확인**했습니다.
실제 게임에서 확인한 것은 따로 적었습니다. 맨 아래 [아직 남은 것](#아직-남은-것) 에 실제 게임에서 볼 것을 모아뒀습니다.

## 2026-09-17

### 프로젝트 폴더에 파일을 쓸 수 없음
- **증상**: 초파리 뉴런 데이터를 받았는데 `E:\Project\MOLLI` 안으로 옮기지 못함.
- **원인**: 폴더 권한이 Users 계정에 읽기·실행만 줘져 있었다.
- **해결**: 사용자가 관리자 PowerShell 에서 `icacls "E:\Project\MOLLI" /grant "${env:USERNAME}:(OI)(CI)M" /T` 를 실행했다. 이후 107개(20.76MB) 이동 완료.

### 향기 추적 학습이 100스텝 만에 NaN
- **증상**: 학습을 시작하면 금방 수치가 망가진다.
- **원인**: 선형 Q 학습이 발산했다. Q 값이 1e35 까지 커진 뒤 Infinity − Infinity 로 NaN 이 됐다.
- **해결**: 가중치 갱신량을 켜진 KC 수로 나누고, 도파민(TD 오차)을 ±2 로 제한했다. 3000판 동안 NaN 이 없었고, 성공률은 92% → 100%, 걸음 수는 33 → 6 이 됐다.

### 지뢰찾기 2000판 승률 0%
- **원인**:
  - 주변 5×5 칸을 날것 그대로 넣었는데, 같은 패턴이 거의 다시 나오지 않아 일반화할 게 없었다.
  - 정보가 전혀 없는 먼 칸까지 후보에 넣어서 거기서 계속 죽었다.
- **해결**: 후각엽처럼 전처리를 넣었다. 제약 전파와 정규화로 특징 51개를 만들고, 후보는 열린 칸에 붙은 칸으로 제한했다. 승률 29% → 72%.

### 3D 몰리가 이상하게 그려짐
- **모자챙이 얼굴을 가림**: 카메라 높이가 얼굴보다 낮아서 챙의 밑면만 보였다. 시선 높이를 올리고 챙을 줄였다.
- **눈이 한쪽만 보임**: 화가 알고리즘이 면 중심 깊이로만 정렬해서 먼 쪽 눈이 머리 면에 묻혔다. 얼굴 파트에 그리기 우선순위(`layer`)를 줬다.
- **곡괭이가 안 보임**:
  - 손잡이를 팔과 같은 색으로 칠해 팔에 묻혔다 → 나무색으로 바꿨다.
  - 팔 회전 부호가 반대여서 뒤로 휘둘렀다 → 부호를 고쳤다.
  - 아래로 내리찍으면 타격점이 늘 발밑이라 앞에 둔 광석 블록과 어긋났다 → 발밑 구덩이를 파는 동작으로 바꿨다.

### 창이 가려지면 봇이 멈춤
- **원인**: 숨은 창에서는 `requestAnimationFrame` 이 멈춘다. 타이머로 바꿔도 창이 완전히 가려지면 브라우저가 초당 1회로 묶는다.
- **해결**: `setInterval` 로 바꾸고, 브라우저와 게임 창을 나란히 두게 했다. 가려지면 경고를 띄우고 워치독이 키를 놓는다.

### 새 코드가 브라우저에 안 먹음
- **원인**: 브라우저 캐시.
- **해결**: 당시에는 Ctrl+F5 로 넘어갔다. 09-19 에 nginx 에 `no-store` 를 넣어 근본적으로 해결했다.

### 시작 화면에서부터 막히고 재시작을 못함
- **원인**: 무슨 화면인지 모른 채 WASD 만 눌렀다.
- **해결**: 화면을 플레이·레벨업·메뉴·사망으로 나누고, 사용자가 각 화면을 가르치게 했다. 이때 넣은 "메뉴에서 먹히는 키 찾기"가 바로 다음 문제를 일으켰다.

### "몰리가 자꾸 게임을 꺼"
- **원인**: 키 찾기가 `enter → space → down → ESC` 순으로 눌러봤다. ESC 가 게임을 일시정지하거나 종료했다.
- **해결**:
  - 키 찾기를 통째로 없앴다. 화면별 키는 사람이 지정하고, 지정하지 않으면 아무것도 누르지 않는다.
  - 브릿지 허용 목록에서 ESC 를 뺐다. 코드에 버그가 있어도 ESC 는 나가지 않는다.
  - 키 간격을 1.2초로 늘렸다.

### 체력을 모르고, 보상이 "픽셀 세기"였음
- **원인**: 보상이 적·젬 픽셀의 증감이라는 대리 지표였다. 맞아도 아무 신호가 없었고, 구석으로 도망가면 오히려 보상을 받았다.
- **해결**: 체력바 영역을 지정하게 하고, 채워진 비율이 줄면 음의 보상을 준다(픽셀 추정치의 12배). 이후 "맞지 않기"를 직접 배운다.

### 레벨업 화면을 구분 못함
- **원인**: 화면을 밝기·움직임 등 숫자 4개로만 비교했다. 레벨업과 사망이 같은 값으로 나왔다.
- **해결**: 화면을 16×10 썸네일로 통째로 비교한다.

### 적 떼 사이의 틈을 못 봄
- **원인**: 입력이 8방향 × 4링 = 밀도 32개였다. 빽빽한 쪽과 틈이 있는 쪽이 똑같이 보였다.
- **해결**: 캐릭터 주변을 24×24 격자로 보고, 방향마다 탈출 여지·압박·젬을 뽑는다. 규칙 기반과 학습을 섞는 슬라이더를 붙였다(기본은 규칙 100%).

### 마우스 클릭이 메인 모니터로 튐
- **원인**: `GetSystemMetrics(0/1)` 은 주 모니터 크기만 돌려준다. 게임이 보조 모니터에 있으면 좌표가 틀린다.
- **해결**: 사용자 지시로 브라우저와 브릿지 양쪽의 클릭 코드를 지웠다. 키보드만 쓰니 게임 창 하나만 공유해도 된다.

## 2026-09-18

### 무엇이 실패했는지 알 수 없음
- **해결**: 측정 수단을 붙였다.
  - 키를 누른 뒤 화면이 실제로 넘어갔는지 기록하고, 화면별 성공률을 보여준다.

  - 보상과 생존 시간의 상관계수를 낸다.

### LLM 모델 고르기
- **qwen3-vl:8b 가 90초 쓰고 빈 답**: thinking 모델이라 출력이 `thinking` 으로 빠졌고, 토큰 한도 200 을 거기서 다 썼다. `think:false` 도 무시한다. 한도를 900 으로 올리고, 비면 `thinking` 이라도 읽게 했다. 결론적으로 thinking 모델은 이 용도에 맞지 않는다.
- **처음 부를 때 45초**: 모델이 VRAM 에서 내려가 있었다. `keep_alive: 30m` 으로 붙잡아 둔다.
- **llama3.2-vision:11b 실행 불가**: Ollama 0.34.2 가 `mllama` 구조를 읽지 못한다. 우회할 수 없다.
- **qwen 은 제외**: 사용자 지시(중국 모델 안 씀). **gemma3:12b 를 채택**했다(웜 5.6초, 카드 정확히 읽음).
- **브릿지 SyntaxError**: `global OLLAMA` 선언보다 `default=OLLAMA` 가 먼저 나왔다. 선언을 `main()` 첫 줄로 옮겼다.
- **LLM 을 기다리는 동안 워치독이 멈춤**: 블로킹 호출이 이벤트 루프를 막았다. 별도 스레드(`asyncio.to_thread`)로 뺐다.

### Docker Desktop 이 에러 창을 띄운 채 멈춤
- **증상**: 로그에 `error-dialog-from-backend`, WSL `docker-desktop` 이 올라오지 않음.
- **해결**: 한참 뒤 저절로 올라왔다(29.7.2). 11435 포트에 테스트 컨테이너를 띄워 GPU 패스스루(RTX 5060 Ti)를 확인했다. 확인 전에는 로컬 Ollama 를 지우지 않았다.

### 서브컴(182.230.211.85)에 닿지 않음
- **경과**: 처음에 공인 IP 라는 이유로 찔러보지 않았다. 사용자 지적을 받고 확인했다.
- **결과**: ping 은 시간 초과, 포트는 11434·22·3389·445·135·80·443 전부 닫혀 있었다. 경로는 이더넷 → 공유기로 정상이었다(VPN 문제 아님). 원인은 받는 쪽에 있었다(꺼져 있음, 방화벽, 또는 다른 장비의 주소).
- **결정**: Ollama 는 로컬에 두고, 나중에 옮길 때 `--ollama http://서브컴IP:11434` 만 붙인다.

### LLM 이 레벨업을 한 번도 판단하지 않았음
- **원인**: 화면 판별(`classify`)은 사용자가 가르친 샘플과의 거리만 쟀다. 가르친 게 없으면 움직임만 보고 play/menu 둘 중 하나를 골랐다. `levelup` 이 나올 수 없어서 LLM 카드 선택 코드가 실행된 적이 없었다.
- **해결**: "화면 종류도 LLM 이 판별" 을 넣었다. 화면이 멈췄고 처음 보는 화면일 때만 한 번 묻고 그 썸네일을 기억한다. 가짜 화면으로 3/3.

### 모델 28GB 가 너무 큼
- **원인**: 디스크와 VRAM 을 헷갈린 것이었다. VRAM 에는 쓰는 모델 하나(7.5GB)만 올라간다.
- **해결**: 쓸 수 없는 모델 3개를 지웠다. 디스크 26.1GB → 7.6GB.

### start.ps1 한글이 깨지고 실행이 안 됨
- **원인**: `.ps1` 을 BOM 없이 저장해서 PowerShell 5.1 이 CP949 로 읽었다.
- **해결**: UTF-8 BOM 으로 저장한다. 파일 상단에 주석으로 남겼다.

### "LLM 모델이 없다"
- **원인**: `docker compose --profile ollama` 가 빈 볼륨으로 11434 를 가져갔다. 네이티브에 있던 gemma3 는 저장 위치가 달라 따라오지 않았다.
- **해결**: 다시 받지 않고 이미 있는 모델을 볼륨으로 복사했다(`import-models.ps1`). 도커 쪽이 오히려 빨랐다(웜 2.2초).

### 메뉴·결과 화면에서 엉뚱한 걸 고름
- **원인**: 그림을 보면서 동시에 판단하게 했더니 잘 보고도 번호를 틀렸다(2/7).
- **해결**: 세 단계로 나눴다. 이후 메뉴와 레벨업 모두 이 구조를 쓴다.
  1. 그림을 보고 항목 목록과 커서 위치를 읽는다.
  2. 글자만 보고 무엇을 고를지 정한다(이미지를 주지 않음).
  3. 몇 칸 옮길지는 코드가 계산한다.

  결과는 2/7 → 6/7 이었다. 답은 한국어로 받는다.

### 레벨업 문제 다섯 가지
- **추론 전에 엔터가 나감**: 레벨업이 막 떴을 때 한순간 "플레이 중" 으로 읽혔다. 같은 판정이 450ms 이어져야 키를 누르게 했다(이동키를 놓는 것만은 즉시).
- **새로고침·건너뛰기·삭제를 모르고, 추론과 다른 카드를 고름**: 레벨업만 아직 "몇 번째 카드냐" 를 직접 물었는데, 모델은 이름은 맞히고 번호는 틀렸다. 메뉴와 같은 단계 구조로 바꿨다.
- **피격을 잘 못 잡음**: 사용자 제안대로 화면 가운데 캐릭터가 빨개지는 것으로 잡는다(평소값 대비 +0.1). 번쩍이는 동안에는 평소값을 갱신하지 않는다.
- **보상 상자·부활을 모름**: "지금 화면이 뭔지 물어보기" 버튼을 넣었다. 부활은 `YOU DIED` 글자가 아니라 "무엇을 하라고 하는지" 로 구분하게 해서 4/4.
- **내가 낸 사고**: 패치 범위를 잘못 잡아 메뉴 처리 코드를 덮어썼다. `node --check` 는 문법만 봐서 통과했다. 복구했고, 선언 없이 호출되는 이름을 찾는 검사기(`check_refs.js`)를 만들어 이후 매번 돌린다.

### 메모가 모든 화면에 따라다님
- **원인**: 메모가 전역 목록이라 관계없는 화면의 판단에도 전부 들어갔다.
- **해결**: 메모를 화면 썸네일에 붙였다(`{t, note}`). 그 화면일 때만 그 메모가 들어간다.

### 화면 종류가 고정돼 있어 "카드 선택 화면" 을 못 알아들음
- **해결**: 말로 설명하면 새 화면 종류를 만든다(예: "캐릭터 선택").

  - LLM 이 읽은 카드 이름이 화면 글자에 실제로 있는지 맞춰본다.
- **버그**:

### 섹션 제목을 자꾸 누름

### 링크와 일반 글자를 구분 못 함
- **사실 (사용자 + 실측)**: 정보 창의 링크 글자는 초록 — 밝은 연두 `(223,250,53)`, 번진 가장자리 `(96,108,32)`. 제목·창 이름은 흰색.
- **해결**: OCR 줄마다 글자 상자 안의 링크 색(초록 > 빨강, 초록 − 파랑 > 50)을 세어 링크인지 가른다. 창 본문 안에서 링크가 아닌 줄은 프롬프트에서 `[--] … (plain text in a window — not clickable)` 로 번호를 지우고, 골라도 안 누른다. 실제 정보 창 19줄을 모두 맞게 갈랐다 (제목 5줄·그림 속 깨진 글자는 일반, 링크 10줄은 링크). 섹션 제목 이름 목록에 없는 쪽에서도 색으로 걸러진다.

### 설명서 속 그림을 창으로 착각 / 코드 창 이름(main)만 찌름
- **사실 (사용자)**: 게임에서 창 안에 창은 있을 수 없다. 'First Program' 쪽의 `▶ ▷ main ─ ✕` 는 **그림**이다. 코드 창은 제목줄의 이름(`main`)을 누르면 **파일 이름 바꾸기**가 되고, 코드는 그 **아래 편집 칸**을 눌러야 쓸 수 있다. 창을 다른 창 위로 끌면 **도킹**된다(설명서).
- **원인**: 그림 속 제목줄도 진짜와 똑같은 `(86,86,86)` 이다. 색 덩어리 방식에서는 바깥 창 덩어리에 묻혀 후보에도 안 올라왔다. 링크 판별은 창 버튼의 올리브 `(96,115,13)` 까지 링크로 셌다.
- **해결**:
  - 진짜 창 본문 안을 따로 훑어 제목줄 색이 창 폭 8% 넘게 이어지는 띠를 **그림**으로 본다. 그 둘레 글자는 `[--] … (text inside a PICTURE)` 로 번호를 지우고 안 누른다.
  - 진짜 창 제목줄 위의 글자(창 이름)는 `[--] … (a window's NAME — clicking renames)` 로 지우고 안 누른다.
  - 코드는 `{"type":"code","window":W,"text":"..."}` — 그 창 제목줄 아래 편집 칸(폭 15% 안쪽, 줄 번호 칸 피함)을 누르고 입력.
  - 링크는 글자 속 밝은 연두(초록 > 170)만 센다 → 버튼 올리브가 빠진다.
  - 확인: 지금 화면에서 그림 1개(그림 속 `main`·`✕` → 그림), 진짜 `main` → 창 이름, 설명 13줄 → 일반. 목차 화면 링크 10·제목 5 판별 그대로.

### 밑줄 없는 연두 글자(True·False·숫자)를 링크로 봄
- **사실 (사용자)**: 링크는 **연두 + 밑줄**. 설명서의 `True`, `False`, `200` 같은 연두는 코드 강조일 뿐 링크가 아니다.
- **실측**: 밑줄은 글자 아래 한 줄에 연두가 끊김 없이 길게 이어진다 (`Hay` 33px, `harvest` 83px). 강조 글자는 획뿐이라 어느 줄도 12px 이하.
- **해결**: 원래 크기로 보고, 글자 높이의 0.8배 이상 이어지는 연두 가로줄이 있어야 링크. 한 OCR 줄에 밑줄이 여러 개면 밑줄마다 쪼개 따로 번호를 준다 (`External Editor First` → `External Editor` / `First`, `do a flip harvest pet_the_piggy` → 셋).
- **같이 찾은 버그**: 창 맨 윗줄이 모서리 경계라 반쯤만 제목줄 색이면, 제목줄이 없다고 보고 정보 창을 통째로 버렸다 (harvest 설명 쪽). 위 4줄까지는 건너뛰고 꽉 찬 줄부터 잰다. 이걸 고치자 그림 속 제목줄도 후보로 잡히면서 바깥 창 본문까지 그림으로 늘어났다 → 그림은 제목줄 띠 높이로 줄인다.
- 확인: First Program(그림 속 `main`·`x` 만 그림), harvest 설명(링크 0 — 연두 강조 4개 모두 일반), 목차(링크 14개, 합친 줄 쪼갬) 모두 맞음.

### 코드 창을 무한히 만들고, 여러 창을 한 덩어리 "W1" 로 봄
- **증상**: 자율 중 `+` 를 계속 눌러 f0, f1, f3 … 이 쌓였다. 겹치거나 붙은 창들을 한 덩어리로 보고 이상한 걸 옮기려 했다.
- **사실 (사용자)**: 회색 제목줄에 적힌 글자가 그 창의 이름이다. 그 아래 진한 회색을 누르면 코드 입력. 배경에서 스크롤 가능, 창 크기 조절 가능, 필요 없는 창은 ✕ 로 닫는다. 창은 앞뒤로 쌓이거나 위아래로 붙는다(도킹).
- **원인**: 창 = "회색이 이어진 덩어리" 로 봤다. 붙거나 쌓인 창은 회색이 이어져 하나가 된다. `+` 를 막는 장치가 없었다. W0·W1 은 내가 지어낸 번호라 LLM 이 실제 창과 못 맞췄다.
- **해결**:
  - 창 = **제목줄 띠 하나**. 높이가 화면 2~6% 인 회색 가로 띠를 찾고(버튼·이름 글자로 끊긴 틈은 잇는다), 그 아래 진한 회색 본문을 **다음 제목줄이 나올 때까지** 잰다 → 붙은 f0/f1 이 나뉜다.
  - 띠 바로 옆(바깥으로 훑어 배경보다 먼저)이 양쪽 다 본문이면 남의 창 안 = 그림.
  - 이름 = 제목줄 위 OCR 글자(띄어쓰기 붙임, `ø`→`0`). 못 읽으면 제목줄만 잘라 3배로 다시 OCR (`f1` 이 이렇게 읽혔다). 종류 = 제목줄 버튼: 왼쪽에 둘(▶ ▷) 이면 코드 창, ↩ 하나면 정보 창.
  - LLM 에게는 이름으로 준다 (`"f0" — code window …`). `move_window`·`code`·새 `close_window`(✕) 가 이름을 받는다.
  - `+` 는 코드 창이 하나라도 있으면 막는다.
  - 제목줄 위 글자(✕ 를 OCR 한 `x` 등)는 링크가 아니다. 밑줄 판정에 얇음 검사(위아래 4px 도 연두면 버튼).
- **테스트용**: 게임 창이 다른 창에 가려져 있어도 `PrintWindow` 로 게임 내용만 찍는다 (스크린샷 비교용, 페이지는 화면 공유를 쓴다).
- 확인 (스크린샷 4장): 지금 화면 info·f0·(f1)·f3 따로, 뒤에 숨은 창 조각은 그림 처리. First Program 그림 정상. 목차 링크 14개(`x` 제외). harvest 설명 링크 0, 창 이름 `ma in`→`main`.

### 코드는 썼는데 문법이 망가지고, 실행을 안 함
- **원인**: 한 글자씩 치면 게임 편집기의 **자동 완성 창**(설명서: "Press Tab to insert the code completion")과 **자동 들여쓰기**가 끼어든다. 쓰고 나서 ▶ 를 누르는 단계가 없었다.
- **해결** — `code` 행동이 "쓰고 → 보고 → 실행 → 보고" 를 한 번에 한다:
  1. 편집 칸 클릭 → `Ctrl+A` → **클립보드 붙여넣기** (브릿지 `paste`). 자동 완성·들여쓰기가 안 낀다.
  2. 그 창 본문만 3배로 OCR 해서 들여쓰기(줄 x 위치, 4칸 = 한 단계)까지 되살려 쓴 코드와 비교. 띄어쓰기·`l`/`1`·`O`/`0` 같은 OCR 혼동은 무시, 들여쓰기 단계·줄 수는 엄격.
  3. 다르면 한 번 더, 그래도 다르면 실행하지 않고 "편집기에 보이는 코드" 를 LLM 에게 돌려준다.
  4. 같으면 그 창 제목줄 맨 왼쪽 ▶ 를 누르고 2초 뒤 화면 변화와 오류 글자(error, exception, not defined …)를 보고한다.
  - ▶ 만 누르는 `run` 행동도 있다. LLM 에게 "조금 쓰고 실행하고 결과 보고 고쳐라" 로 안내.
- **사고**: 클립보드 함수를 시험하다 사용자 클립보드의 **이미지**를 지웠다. 되돌리기는 글자만 된다 — 클립보드에 글자가 아닌 것이 있으면 붙여넣기 뒤에 되돌리지 못한다.

### 설명서를 스크롤하지 않고, 다 읽어도 안 돌아감
- **해결**: 설명서 한 쪽(목차 아님)이 열려 있으면 LLM 행동 대신 코드가 순서대로 한다 — 보이는 부분 읽기 → 정보 창 본문 위에서 휠 5칸 → 화면이 안 바뀌면 끝(최대 8번) → 제목줄 맨 왼쪽 올리브 버튼(↩)으로 목차로. 다 읽은 쪽은 `dict.pagesRead` 에 남겨 LLM 에게 "다시 열지 마" 로 알린다. LLM 이 직접 쓰는 `{"type":"back"}` 도 있다.
- 창 제목줄 버튼은 가운데 줄만 보면 흰 그림(↩ ─ ✕ ▶)에 막혀 쪼개진다 → 위·가운데·아래 세 줄 중 하나라도 올리브면 버튼. 지금 화면에서 7개 모두 정확 (정보 창 ↩ 3.0%·─ 43.7%·✕ 46.3%, 코드 창 ▶ 52.9%·▷ 55.5%·─ 72.8%·✕ 75.4%).

### 느림
- **실측** (gemma3:12b, RTX 5060 Ti 16GB): 답 쓰기가 초당 약 30토큰이라 시간 대부분이 **답을 쓰는 데** 든다. 그림 읽기는 0.2~1.9초.
- **해결**: 단어 수집은 필요할 때만, 정보 최대 5개, 문장 한 줄. Ollama `format: "json"` 으로 앞뒤 잡담을 없앴다(8.4초 → 6.1초). 답 상한 250/350/700토큰. 로그에 "읽기 몇 초 · 답 쓰기 몇 초 · 몇 토큰" 이 찍힌다.
- **모델**: 이 PC 에서 중국산이 아닌 비전 모델 중엔 gemma3:12b 가 최선. 4b 는 판단이 약하고, mistral-small 24b 는 16GB 에 빠듯하다. 양자화를 더 내리면 글자 읽기만 나빠진다.

### 봇이 게임을 꺼버림
- **증상**: 자율 플레이 중 게임이 꺼졌다.
- **원인 (게임 로그 `%USERPROFILE%\AppData\LocalLow\TheFarmerWasReplaced\TheFarmerWasReplaced\Player.log`)**: 튕긴 게 아니라 정상 종료. 테마를 다시 불러오는 장면 전환(= 메인 메뉴로 나감) 직후 종료 → 메인 메뉴에서 Quit 을 누른 것으로 보인다. 메인 메뉴로 나간 경로는 확실하지 않다 — 뜻을 모르는 오른쪽 위 `⇈` 아이콘 둘레를 누른 것으로 의심. 페이지 로그로 확인 대기.
- **해결** (말이 아니라 구조로 막음):
  - 브릿지: 클릭·스크롤·끌기 지점이 게임 내용 영역 밖(제목줄 ─ □ ✕, 테두리)이면 무조건 거절. 실제 게임 창에서 확인 — ✕ (99%, 1.2%) 거절, `i` 버튼·가운데 통과.
  - Quit / Exit / Main Menu / 종료 / 나가기 / 메인 메뉴 글자는 프롬프트에서 `[XX]` 로 번호를 지우고, 골라도 실행 안 함.
  - `⇈` 아이콘 둘레는 클릭 금지 구역 (뜻을 알 때까지).
  - 자율 중 메인 메뉴(타이틀)로 나오면 즉시 정지.

### 창이 밭을 가림 / 창 안의 그림을 자꾸 누름
- **원인**: LLM 이 무엇이 중요한지(밭) 모르고, 창 안의 그림이 그림인지 모른다. 드래그도 없었다.
- **해결**: 화면 배치를 색으로 코드가 잰다 (실측: 창 제목줄·테두리 `(86,86,86)`, 본문 `(46,46,46)`, 배경 푸른 회색, 밭·드론 주황·황토).
  - 창 = 제목줄 색 덩어리 + 그 아래 본문 색이 이어지는 데까지. 링크가 빽빽한 줄에서 끊기지 않게 화면 높이 2.5% 까지는 봐준다.
  - 밭 = 창 밖 따뜻한 색 중 **가장 큰 덩어리**. 창에 거의 다 가려지면 삐져나온 드론 날개를 밭으로 착각하므로, 기억해 둔 밭보다 절반 넘게 작으면 기억을 쓴다.
  - 자율 걸음마다 LLM 에게 묻기 **전에** 밭을 가린 창을 제목줄 빈 곳을 잡아 밭 옆으로 끌어 둔다 (브릿지 `drag`: 누른 채 20번에 나눠 이동).
  - LLM 에게 배치(밭 위치, 창 W0·W1, 가림 여부)를 알려 주고 `move_window` 행동을 준다.
  - 창 본문 안의 좌표 클릭(`click_at`)은 거절 → 그림을 못 누른다. 창 안에서는 OCR 글자 링크만.
  - **게임은 창끼리 겹치게 놓지 못한다** (사용자 확인). 옮길 자리는 다른 창과 겹치면 후보에서 아예 빼고, 화면 전체를 2% 간격으로 훑어 빈자리를 찾는다. 빈자리가 없으면 끌지 않고 "놓을 데 없음" 으로 알린다. 하나 옮길 때마다 다시 재고, 끈 뒤에는 실제로 옮겨졌는지 확인한다. LLM 에게는 자리가 없으면 창 제목줄의 `−` 로 줄이라고 알려 준다.
  - 확인: 실제 스크린샷 2장에서 창 2개·밭 정확. 정보 창을 밭 위에 덮은 합성 화면에서 '가림' 으로 잡고 밭 왼쪽(15%)으로 옮길 자리를 골랐다. 밭 왼쪽을 코드 창 셋으로 막은 합성 화면에서는 창 4개를 다 찾고, 어떤 창도 다른 창과 겹치는 자리로 보내지 않았다 (큰 창은 겹치지 않는 자리 중 밭을 가장 덜 가리는 곳 — 가림 절반). 실제 끌기는 `--live` 로 확인 대기.

## 되풀이된 교훈

- **LLM 은 못 읽으면 지어낸다.** "날개", "슈퍼 소울" 모두 같은 병이었다. 답을 그대로 믿지 말고 두 번 읽기, OCR, 사전처럼 코드로 확인한다.
- **LLM 에게는 이름을 묻고, 번호와 키는 코드가 센다.** 번호를 물으면 틀린다.
- **누른 뒤에는 넘어갔는지 확인한다.** 한꺼번에 누르고 끝내는 방식은 메뉴·레벨업·확정 버튼에서 모두 문제가 됐다.
- **문법 검사는 코드가 사라진 걸 못 잡는다.** 큰 파일은 앵커 확인 치환만 쓰고, 참조 검사(`check_refs.js`)와 브라우저 콘솔까지 본다.
- **PowerShell 파일은 UTF-8 BOM 으로 저장한다.**
- **`localhost` 는 IPv6 를 먼저 시도한다.** 127.0.0.1 에만 묶은 서비스는 127.0.0.1 로 확인한다.
- **캐시**: 페이지가 이상하면 먼저 Ctrl+F5.
- **추측하지 말고 실제 화면으로 돌려본다.** 10-28 의 '안 움직임' 은 처음 의심(답 잘림)과 진짜 원인(`action` 키 없음)이 달랐다. 게임 창을 찍어 페이지와 똑같은 프롬프트로 돌리면 몇 분이면 나온다.
- **gemma3 12B 에게는 한 번에 한 가지만 시킨다.** 여러 가지를 한 프롬프트에 넣으면 앞의 일부만 한다. 중요한 건 JSON 틀 맨 앞에 두거나 따로 묻는다.
- **말로 막지 말고 구조로 막는다.** "제목은 누르지 마" 는 안 들었고, 번호를 지우니 들었다.
- **좌표는 LLM 에게 묻지 않는다.** 글자는 OCR 줄 번호, 아이콘은 색으로 코드가 찾는다.
- **이 표의 규칙부터 본다.** 10-28 에 09-18 규칙(중국 모델 금지)을 안 보고 Qwen 을 추천했다.
