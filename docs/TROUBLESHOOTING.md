# 트러블슈팅 기록

MOLLI 를 만들면서 부딪힌 문제와 원인, 고친 방법을 날짜순으로 적었습니다. 날짜와 순서는 한국 시간 기준입니다.

항목마다 **증상 → 원인 → 해결** 순서입니다. 뱀서 관련 수정은 대부분 **가짜 화면·가짜 LLM 으로만 확인**했습니다.
실제 게임에서 확인한 것은 따로 적었습니다. 맨 아래 [아직 남은 것](#아직-남은-것) 에 실제 게임에서 볼 것을 모아뒀습니다.

## 2026-09-17

### 프로젝트 폴더에 파일을 쓸 수 없음
- **증상**: 초파리 뉴런 데이터를 받았는데 `E:\Project\MOLLI` 안으로 옮기지 못함.
- **원인**: 폴더 권한이 Users 계정에 읽기·실행만 줘져 있었다.
- **해결**: 사용자가 관리자 PowerShell 에서 `icacls "E:\Project\MOLLI" /grant "${env:USERNAME}:(OI)(CI)M" /T` 를 실행했다. 이후 107개(20.76MB) 이동 완료.

### 향기 추적 학습이 100스텝 만에 NaN
- **증상**: 학습을 시작하면 금방 수치가 망가진다.
- **원인**: 선형 Q 학습이 발산했다. Q 값이 1e35 까지 커진 뒤 Infinity − Infinity 로 NaN 이 됐다.
- **해결**: 가중치 갱신량을 켜진 KC 수로 나누고, 도파민(TD 오차)을 ±2 로 제한했다. 3000판 동안 NaN 이 없었고, 성공률은 92% → 100%, 걸음 수는 33 → 6 이 됐다.

### 지뢰찾기 2000판 승률 0%
- **원인**:
  - 주변 5×5 칸을 날것 그대로 넣었는데, 같은 패턴이 거의 다시 나오지 않아 일반화할 게 없었다.
  - 정보가 전혀 없는 먼 칸까지 후보에 넣어서 거기서 계속 죽었다.
- **해결**: 후각엽처럼 전처리를 넣었다. 제약 전파와 정규화로 특징 51개를 만들고, 후보는 열린 칸에 붙은 칸으로 제한했다. 승률 29% → 72%.

### 3D 몰리가 이상하게 그려짐
- **모자챙이 얼굴을 가림**: 카메라 높이가 얼굴보다 낮아서 챙의 밑면만 보였다. 시선 높이를 올리고 챙을 줄였다.
- **눈이 한쪽만 보임**: 화가 알고리즘이 면 중심 깊이로만 정렬해서 먼 쪽 눈이 머리 면에 묻혔다. 얼굴 파트에 그리기 우선순위(`layer`)를 줬다.
- **곡괭이가 안 보임**:
  - 손잡이를 팔과 같은 색으로 칠해 팔에 묻혔다 → 나무색으로 바꿨다.
  - 팔 회전 부호가 반대여서 뒤로 휘둘렀다 → 부호를 고쳤다.
  - 아래로 내리찍으면 타격점이 늘 발밑이라 앞에 둔 광석 블록과 어긋났다 → 발밑 구덩이를 파는 동작으로 바꿨다.

### 창이 가려지면 봇이 멈춤
- **원인**: 숨은 창에서는 `requestAnimationFrame` 이 멈춘다. 타이머로 바꿔도 창이 완전히 가려지면 브라우저가 초당 1회로 묶는다.
- **해결**: `setInterval` 로 바꾸고, 브라우저와 게임 창을 나란히 두게 했다. 가려지면 경고를 띄우고 워치독이 키를 놓는다.

### 새 코드가 브라우저에 안 먹음
- **원인**: 브라우저 캐시.
- **해결**: 당시에는 Ctrl+F5 로 넘어갔다. 09-19 에 nginx 에 `no-store` 를 넣어 근본적으로 해결했다.

### 시작 화면에서부터 막히고 재시작을 못함
- **원인**: 무슨 화면인지 모른 채 WASD 만 눌렀다.
- **해결**: 화면을 플레이·레벨업·메뉴·사망으로 나누고, 사용자가 각 화면을 가르치게 했다. 이때 넣은 "메뉴에서 먹히는 키 찾기"가 바로 다음 문제를 일으켰다.

### "몰리가 자꾸 게임을 꺼"
- **원인**: 키 찾기가 `enter → space → down → ESC` 순으로 눌러봤다. ESC 가 게임을 일시정지하거나 종료했다.
- **해결**:
  - 키 찾기를 통째로 없앴다. 화면별 키는 사람이 지정하고, 지정하지 않으면 아무것도 누르지 않는다.
  - 브릿지 허용 목록에서 ESC 를 뺐다. 코드에 버그가 있어도 ESC 는 나가지 않는다.
  - 키 간격을 1.2초로 늘렸다.

### 체력을 모르고, 보상이 "픽셀 세기"였음
- **원인**: 보상이 적·젬 픽셀의 증감이라는 대리 지표였다. 맞아도 아무 신호가 없었고, 구석으로 도망가면 오히려 보상을 받았다.
- **해결**: 체력바 영역을 지정하게 하고, 채워진 비율이 줄면 음의 보상을 준다(픽셀 추정치의 12배). 이후 "맞지 않기"를 직접 배운다.

### 레벨업 화면을 구분 못함
- **원인**: 화면을 밝기·움직임 등 숫자 4개로만 비교했다. 레벨업과 사망이 같은 값으로 나왔다.
- **해결**: 화면을 16×10 썸네일로 통째로 비교한다.

### 적 떼 사이의 틈을 못 봄
- **원인**: 입력이 8방향 × 4링 = 밀도 32개였다. 빽빽한 쪽과 틈이 있는 쪽이 똑같이 보였다.
- **해결**: 캐릭터 주변을 24×24 격자로 보고, 방향마다 탈출 여지·압박·젬을 뽑는다. 규칙 기반과 학습을 섞는 슬라이더를 붙였다(기본은 규칙 100%).

### 마우스 클릭이 메인 모니터로 튐
- **원인**: `GetSystemMetrics(0/1)` 은 주 모니터 크기만 돌려준다. 게임이 보조 모니터에 있으면 좌표가 틀린다.
- **해결**: 사용자 지시로 브라우저와 브릿지 양쪽의 클릭 코드를 지웠다. 키보드만 쓰니 게임 창 하나만 공유해도 된다.

## 2026-09-18

### 무엇이 실패했는지 알 수 없음
- **해결**: 측정 수단을 붙였다.
  - 키를 누른 뒤 화면이 실제로 넘어갔는지 기록하고, 화면별 성공률을 보여준다.
  - 보상 구성(피격·탈출·젬·시간 비율)을 보여준다. 피격이 0% 면 체력바를 못 읽는 것이다.
  - 보상과 생존 시간의 상관계수를 낸다.

### LLM 모델 고르기
- **qwen3-vl:8b 가 90초 쓰고 빈 답**: thinking 모델이라 출력이 `thinking` 으로 빠졌고, 토큰 한도 200 을 거기서 다 썼다. `think:false` 도 무시한다. 한도를 900 으로 올리고, 비면 `thinking` 이라도 읽게 했다. 결론적으로 thinking 모델은 이 용도에 맞지 않는다.
- **처음 부를 때 45초**: 모델이 VRAM 에서 내려가 있었다. `keep_alive: 30m` 으로 붙잡아 둔다.
- **llama3.2-vision:11b 실행 불가**: Ollama 0.34.2 가 `mllama` 구조를 읽지 못한다. 우회할 수 없다.
- **qwen 은 제외**: 사용자 지시(중국 모델 안 씀). **gemma3:12b 를 채택**했다(웜 5.6초, 카드 정확히 읽음).
- **브릿지 SyntaxError**: `global OLLAMA` 선언보다 `default=OLLAMA` 가 먼저 나왔다. 선언을 `main()` 첫 줄로 옮겼다.
- **LLM 을 기다리는 동안 워치독이 멈춤**: 블로킹 호출이 이벤트 루프를 막았다. 별도 스레드(`asyncio.to_thread`)로 뺐다.

### Docker Desktop 이 에러 창을 띄운 채 멈춤
- **증상**: 로그에 `error-dialog-from-backend`, WSL `docker-desktop` 이 올라오지 않음.
- **해결**: 한참 뒤 저절로 올라왔다(29.7.2). 11435 포트에 테스트 컨테이너를 띄워 GPU 패스스루(RTX 5060 Ti)를 확인했다. 확인 전에는 로컬 Ollama 를 지우지 않았다.

### 서브컴(182.230.211.85)에 닿지 않음
- **경과**: 처음에 공인 IP 라는 이유로 찔러보지 않았다. 사용자 지적을 받고 확인했다.
- **결과**: ping 은 시간 초과, 포트는 11434·22·3389·445·135·80·443 전부 닫혀 있었다. 경로는 이더넷 → 공유기로 정상이었다(VPN 문제 아님). 원인은 받는 쪽에 있었다(꺼져 있음, 방화벽, 또는 다른 장비의 주소).
- **결정**: Ollama 는 로컬에 두고, 나중에 옮길 때 `--ollama http://서브컴IP:11434` 만 붙인다.

### LLM 이 레벨업을 한 번도 판단하지 않았음
- **원인**: 화면 판별(`classify`)은 사용자가 가르친 샘플과의 거리만 쟀다. 가르친 게 없으면 움직임만 보고 play/menu 둘 중 하나를 골랐다. `levelup` 이 나올 수 없어서 LLM 카드 선택 코드가 실행된 적이 없었다.
- **해결**: "화면 종류도 LLM 이 판별" 을 넣었다. 화면이 멈췄고 처음 보는 화면일 때만 한 번 묻고 그 썸네일을 기억한다. 가짜 화면으로 3/3.

### 모델 28GB 가 너무 큼
- **원인**: 디스크와 VRAM 을 헷갈린 것이었다. VRAM 에는 쓰는 모델 하나(7.5GB)만 올라간다.
- **해결**: 쓸 수 없는 모델 3개를 지웠다. 디스크 26.1GB → 7.6GB.

### start.ps1 한글이 깨지고 실행이 안 됨
- **원인**: `.ps1` 을 BOM 없이 저장해서 PowerShell 5.1 이 CP949 로 읽었다.
- **해결**: UTF-8 BOM 으로 저장한다. 파일 상단에 주석으로 남겼다.

## 2026-09-19

### "LLM 모델이 없다"
- **원인**: `docker compose --profile ollama` 가 빈 볼륨으로 11434 를 가져갔다. 네이티브에 있던 gemma3 는 저장 위치가 달라 따라오지 않았다.
- **해결**: 다시 받지 않고 이미 있는 모델을 볼륨으로 복사했다(`import-models.ps1`). 도커 쪽이 오히려 빨랐다(웜 2.2초).

### 메뉴·결과 화면에서 엉뚱한 걸 고름
- **원인**: 그림을 보면서 동시에 판단하게 했더니 잘 보고도 번호를 틀렸다(2/7).
- **해결**: 세 단계로 나눴다. 이후 메뉴와 레벨업 모두 이 구조를 쓴다.
  1. 그림을 보고 항목 목록과 커서 위치를 읽는다.
  2. 글자만 보고 무엇을 고를지 정한다(이미지를 주지 않음).
  3. 몇 칸 옮길지는 코드가 계산한다.

  결과는 2/7 → 6/7 이었다. 답은 한국어로 받는다.

### 레벨업 문제 다섯 가지
- **추론 전에 엔터가 나감**: 레벨업이 막 떴을 때 한순간 "플레이 중" 으로 읽혔다. 같은 판정이 450ms 이어져야 키를 누르게 했다(이동키를 놓는 것만은 즉시).
- **새로고침·건너뛰기·삭제를 모르고, 추론과 다른 카드를 고름**: 레벨업만 아직 "몇 번째 카드냐" 를 직접 물었는데, 모델은 이름은 맞히고 번호는 틀렸다. 메뉴와 같은 단계 구조로 바꿨다.
- **피격을 잘 못 잡음**: 사용자 제안대로 화면 가운데 캐릭터가 빨개지는 것으로 잡는다(평소값 대비 +0.1). 번쩍이는 동안에는 평소값을 갱신하지 않는다.
- **보상 상자·부활을 모름**: "지금 화면이 뭔지 물어보기" 버튼을 넣었다. 부활은 `YOU DIED` 글자가 아니라 "무엇을 하라고 하는지" 로 구분하게 해서 4/4.
- **내가 낸 사고**: 패치 범위를 잘못 잡아 메뉴 처리 코드를 덮어썼다. `node --check` 는 문법만 봐서 통과했다. 복구했고, 선언 없이 호출되는 이름을 찾는 검사기(`check_refs.js`)를 만들어 이후 매번 돌린다.

### 메모가 모든 화면에 따라다님
- **원인**: 메모가 전역 목록이라 관계없는 화면의 판단에도 전부 들어갔다.
- **해결**: 메모를 화면 썸네일에 붙였다(`{t, note}`). 그 화면일 때만 그 메모가 들어간다.

### 화면 종류가 고정돼 있어 "카드 선택 화면" 을 못 알아들음
- **해결**: 말로 설명하면 새 화면 종류를 만든다(예: "캐릭터 선택").
- **버그**: `load()` 를 정의하기 전에 불렀다(TDZ). 문법 검사도 참조 검사도 못 잡았고 브라우저에서만 드러났다.

### 카드를 고른 뒤 스페이스가 눌림
- **원인**: LLM 으로 고른 뒤에도 "LLM 실패 대비" 고정 키 목록으로 한 번 더 떨어졌다.
- **해결**:
  - 고정 키 목록과 "화면별 누를 키" UI 를 없앴다. LLM 이 없으면 아무것도 누르지 않는다.
  - 한 번 누르면 먹혔는지 확인될 때까지 다시 안 누르게 했다(`pendingMenu`).
- **"가르치기 버튼이 의미 없음"**: 화면 공유가 없으면 아무 말 없이 끝났다. 이제 이유를 알려준다.
- **같은 사고 재발**: 범위 치환으로 함수 23개를 날렸다. 검사기로 바로 복구했고, 이후 이 파일은 앵커 양쪽을 확인하는 치환만 쓴다.

### 글을 잘 못 읽음 — 이미지가 작아서?
- **측정**: 900px 로 줄여도 4/4 였다. 오히려 카드 영역만 잘라 보내면 옆 버튼이 잘려서 0/3 이 됐다. 크기보다 범위가 문제였다.
- **해결**: 전날 "카드 영역을 지정하세요" 라고 한 안내를 뒤집었다. "레벨업에서 읽은 것" 기록을 추가해서 무엇을 읽고 무엇을 골랐는지 남긴다.

### 경험치를 얻었다는 신호가 없음
- **원인**: 젬 값은 매 프레임 최대값으로 정규화한 "방향 분포" 일 뿐이었다. 젬을 먹으면 분포가 흔들려 감점처럼 보일 수도 있었다.
- **해결**: 경험치 바 영역을 지정하면 늘어난 만큼 보상을 준다. 45초 내내 100% 그대로면 영역을 잘못 잡은 것이라 경고한다.

### 다른 창에 키가 들어감
- **원인**: 확인해보니 활성 창이 MapleStory 였다. 브릿지가 활성 창을 가리지 않았다.
- **해결**: "대상 창" 을 지정하게 했다. 다른 창이면 키를 막고, 잡고 있던 키도 놓는다.

### 컴퓨터를 켜도 게임 페이지가 안 뜸
- **원인**: 컨테이너가 `exited` 상태였다. `restart: unless-stopped` 는 직접 멈춘 컨테이너는 다시 살리지 않는다.
- **해결**: 컨테이너를 다시 올렸다. 정책 변경(`always`)은 제안만 했고, "도커는 건드리지 않는다" 규칙에 따라 그대로 뒀다.

### 판 기록이 안 쌓임, 파티클을 적으로 셈, 피격이 틱마다 들어감
- **판 기록**: `dead` 로 읽힐 때만 판을 닫았다. 메뉴로 돌아가거나 다음 판이 시작돼도 닫게 했고, 버려지는 판도 로그에 남긴다.
- **파티클**: 격자를 시간축으로 눌렀다. 올라갈 땐 빠르게(0.5), 내려갈 땐 느리게(0.15). 한 프레임 번쩍임은 0.5 까지만 오르고, 진짜 적은 1.0 이다.
- **피격**: 프레임마다 세서 FPS 가 곧 피격 횟수였다. 400ms 쿨다운을 두고 감점에 `dt` 를 곱했다. 10~60 FPS 에서 모두 8회, 감점 18.00 으로 같다.

### 부활을 사망으로 읽어 판이 쪼개짐
- **해결**: 판별을 더 정확하게 만드는 대신, 틀려도 되돌아오게 했다. `사망` 은 보류만 하고, 15초 안에 플레이가 돌아오면 취소한다. 화면 순서 6가지 모두 통과했다. 처음 2개가 실패로 나온 건 내 기대값 계산 실수(213 을 210 으로 씀)였다.

### 레벨업 순간 경험치가 0% 로 읽힘
- **원인**: 바 색을 저장해두고 비교했는데, 레벨업 때 바가 번쩍이면 색이 달라진다.

- **폰이 이미 쓴 코드가 PC 에 계속 보임**: 코드가 아직 유효한지(`code_active`)를 같이 받는다.

## 2026-09-25

### 폰 지시 기능을 만들다 찾은 것
- **사용자의 실제 브릿지(`--live --remote`)가 켜져 있었음**: 건드리지 않았다. 테스트는 다른 포트와 브릿지 사본으로 해서, 폰 등록 파일도 그대로 뒀다.
- **따옴표 이스케이프가 깨짐**: 편집 도구와 heredoc 이 `\"`, `\n` 을 망가뜨렸다. 파이썬 패치 파일로 고치고, HTML 이스케이프는 `String.fromCharCode(34)` 로 썼다.
- **아직 못 한 것**: 실제 gemma3 로는 돌려보지 않았다. GPU 를 쓰는데 사용자가 다른 작업 중일 수 있었다.

### 모바일 데이터로 폰 접속이 안 됨
- **원인**: `192.168.x` 는 집 공유기 안에서만 통하는 주소다.
- **해결**: Tailscale 로 폰과 PC 를 묶는다. 공유기 포트포워딩은 암호화가 없어서 권하지 않는다.
  - 브릿지와 페이지에 주소마다 용도를 붙였다("밖에서" / "집 와이파이"). 폰이 쓸 수 없는 도커 가상 주소는 뺐다.
  - 쿠키는 주소마다 따로라, 새 주소로는 연결 코드를 한 번 더 넣어야 한다.

### start.ps1 이 멈춘 것처럼 보임 ("안돌아")
- **원인**: 게임 페이지를 `127.0.0.1` 에만 묶었는데 `start.ps1` 은 `localhost` 로 확인했다. `localhost` 는 IPv6 를 먼저 시도해서 2초씩 기다리다 끝나기를 20번 반복했다. 그동안 아무것도 찍지 않았다.
- **해결**: 확인을 `127.0.0.1` 로 한다. 기다리는 시간이 48초 → 0.07초가 됐고, 기다리는 동안 점(`.`)을 찍는다. 브라우저 주소는 `localhost:8743` 그대로 둔다(바꾸면 저장된 설정이 안 보인다).

### 카드를 잘못 고름
- **원인**: 메뉴는 "옮기고 → 다시 읽고 → 엔터" 로 고쳤는데 레벨업만 옛 방식이었다. 커서를 한 칸만 잘못 읽어도, 게임이 첫 입력에 커서를 잡기만 해도 다른 카드가 확정됐다.
- **해결**: 레벨업도 옮길 때마다 다시 읽어서 고른 카드 위일 때만 엔터를 누른다. 가짜 게임에서 예전 방식이 틀리던 세 경우가 모두 맞았다.

### 여전히 카드를 못 고름 — "획득하기"
- **원인**: 사용자 설명대로 카드에서 엔터는 "골라 두기" 이고, "획득하기" 에서 엔터를 쳐야 확정된다. 코드는 카드 엔터로 끝냈다.
- **해결**: 엔터 뒤에도 같은 화면이고 화면 글자에 `획득하기` 같은 버튼이 보이면, 그쪽으로 커서를 옮겨 다시 엔터를 누른다(`confirmIfNeeded`). 방향은 OCR 글자 위치로 잡는다. 카드 엔터로 바로 넘어가면 더 누르지 않는다.

### 나무위키 공략(진화 조합) 붙이기
- **웹 요약 도구를 쓸 수 없었음**: 목록 전체를 옮기지 않으려 했고, 준 예시도 틀렸다. 페이지를 직접 받아서 "조합식" 줄만 뽑았다(147개).
- **"날개", "두개골" 이 지워짐**: 개수 표기를 지우는 정규식이 "개" 를 포함한 이름까지 지웠다. 숫자 + 개(`\d+\s*개`)만 지운다.
- **"검은 심장" 과 "붉은 심장" 을 같은 것으로 봄**: 6자 미만 이름은 정확히 같을 때만 같은 것으로 본다.

### 캐릭터의 시작 무기를 모름
- **해결**: 나무위키에서 캐릭터 209명, 스테이지 33개를 받았다. 캐릭터 선택에서 엔터를 누를 때 화면 글자에서 이름을 찾아 기억하고, 그 캐릭터의 시작 무기를 "이미 가진 것" 으로 친다. 한 글자 이름(`포`)이나 이름이 둘 이상 보이면 기억하지 않는다.

### 캐릭터 선택창에서 정보가 너무 많음
- **원인**: 방금 넣은 두 가지였다.
  - 화면 글자를 전부 주면서 "버튼은 전부 항목에 넣어라" 고 안내해서, 능력치와 설명 줄까지 항목이 될 수 있었다.
  - 목표와 상관없이 캐릭터 정보를 항상 붙였다.
- **해결**: 항목 이름처럼 보이는 짧은 줄만 최대 20줄 준다. 테스트 화면에서 47줄 → 5줄. 캐릭터·스테이지 정보는 목표가 그 얘기를 할 때만 최대 8줄 붙인다. 커서 위치를 잡는 데는 전체 글자를 그대로 쓴다.
- **대기 중**: 메시지가 "특정 붑…" 에서 끊겼다. "특정 부분만 읽게" 라는 뜻인지 답을 기다리는 중.

### 글자를 줬는데도 아이템 이름을 이상하게 읽음
- **원인**:
  - gemma3 가 작은 한글 게임 글씨를 잘 못 읽고, 흐리면 아는 단어로 채운다.
  - OCR 도 한두 글자씩 틀린다(`시금치` → `시급치`).
  - 바로잡는 단계가 없었다. "화면 글자에 있나" 만 확인했다.
- **해결**: 아이템 사전(`game/knowledge/vs_items.json`, 362개)을 만들고, 읽은 이름을 가장 비슷한 실제 이름으로 고친다.
  1. 화면 글자 중 사전과 거의 같은 줄을 찾는다(`마늘 새로운!` 의 뒷말은 뗀다). 이것이 화면에 실제로 있는 카드다.
  2. LLM 이 읽은 이름이 그 카드와 이어지면 사전 철자로 고친다.
  3. 없는 이름을 지어냈으면 같은 자리의 실제 카드로 바꾼다(`슈퍼 소울` → `마늘`).
  4. 화면 글자가 없으면 사전에서 고른다. 후보 둘이 비슷하게 맞으면 고치지 않는다.
- 한글은 자모 단위로 비교한다. 받침 하나 차이가 글자 단위로는 0.67, 자모 단위로는 0.86 이다. `검은 심장` 과 `붉은 심장` 은 서로 바꾸지 않는다.

## 되풀이된 교훈

- **LLM 은 못 읽으면 지어낸다.** "날개", "슈퍼 소울" 모두 같은 병이었다. 답을 그대로 믿지 말고 두 번 읽기, OCR, 사전처럼 코드로 확인한다.
- **LLM 에게는 이름을 묻고, 번호와 키는 코드가 센다.** 번호를 물으면 틀린다.
- **누른 뒤에는 넘어갔는지 확인한다.** 한꺼번에 누르고 끝내는 방식은 메뉴·레벨업·확정 버튼에서 모두 문제가 됐다.
- **문법 검사는 코드가 사라진 걸 못 잡는다.** 큰 파일은 앵커 확인 치환만 쓰고, 참조 검사(`check_refs.js`)와 브라우저 콘솔까지 본다.
- **PowerShell 파일은 UTF-8 BOM 으로 저장한다.**
- **`localhost` 는 IPv6 를 먼저 시도한다.** 127.0.0.1 에만 묶은 서비스는 127.0.0.1 로 확인한다.
- **캐시**: 페이지가 이상하면 먼저 Ctrl+F5.
