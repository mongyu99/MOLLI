# 뱀서 조작 브릿지

브라우저는 화면을 보고 판단할 수는 있지만, 보안 샌드박스 때문에 **다른 프로그램에 키를 보낼 수 없습니다.**
그 마지막 한 칸만 이 스크립트가 담당합니다. 나머지(화면 인식 → 판단 → 로그/그래프)는 전부 브라우저에서 돌아갑니다.

```
게임 화면 ──화면공유──▶ 브라우저 (인식 + 몰리 뇌 판단) ──WebSocket──▶ bridge.py ──키입력──▶ 게임
```

## 실행

보통은 프로젝트 루트의 `start.ps1` 이 도커와 함께 알아서 띄워줍니다.

```
.\start.ps1          안전모드
.\start.ps1 -Live    실제로 키를 누른다
```

브릿지만 직접 띄우려면:

```
bot\.venv\Scripts\python.exe bot\bridge.py
```

이러면 안전모드입니다. 실제 키는 누르지 않고 무엇을 누르려 했는지 콘솔에 찍기만 합니다.
배선이 잘 도는지 먼저 이걸로 확인하세요.

실제로 조작하게 하려면 `--live` 를 붙입니다.

이렇게 직접 띄우면 게임 페이지도 브릿지가 같이 서빙합니다: http://localhost:8743
도커의 nginx가 이미 그 포트를 서빙하고 있다면 `--no-web` 을 붙여 중복을 피하세요
(`start.ps1` 이 알아서 붙입니다). 포트 번호 자체는 그때도 계속 쓰입니다 —
WebSocket Origin 검사의 기준이라서입니다.

## 순서

1. 뱀서를 **창모드**로 띄운다
2. 위 명령으로 브릿지를 실행한다
3. 브라우저에서 http://localhost:8743 을 열고 **뱀서 탭**으로 간다
   (`file://`로 열면 브릿지에 연결되지 않습니다. 반드시 localhost 주소로)
4. `화면 공유` → 뱀서 창 선택
5. `조작 시작` → 게임 창을 클릭해서 활성화

게임 없이 배선만 먼저 확인하려면 `테스트 영상` 버튼을 누르세요. 가짜 화면으로 인식·판단·키 전송까지 그대로 돌아갑니다.

## 중요: 브라우저 창을 가리지 마세요

키 입력이 게임에 들어가려면 게임 창이 활성화돼 있어야 하는데, 그렇다고 브라우저 창을 게임 뒤로
완전히 가리거나 최소화하면 **브라우저가 타이머를 초당 1회로 묶어버려서 봇이 사실상 멈춥니다.**

→ 두 창을 **나란히** 두세요. 게임 창이 활성화돼 있어도 브라우저 창이 화면에 보이기만 하면 정상 속도로 돕니다.
가려지면 페이지 상태창에 경고가 뜨고, 브릿지 워치독이 눌린 키를 놓아줍니다(보지 못하는 상태로 계속 움직이지 않도록).

## 멈춘 화면은 전부 LLM이 지시합니다

처음에는 "어떤 키가 먹는지 모르니 차례로 눌러보게" 만들었다가 **ESC를 눌러서 게임이 꺼지는 문제**가 있었습니다.
그래서 화면마다 누를 키를 미리 지정하게 바꿨는데, 그것도 틀렸습니다:

- 화면마다 눌러야 할 것이 다르니 미리 정해둘 수가 없습니다
- 더 나빴던 건, **LLM이 제대로 고른 뒤에도 그 지정 키가 한 번 더 나갔습니다.**
  레벨업에서 아이템을 고르고 나서 스페이스가 또 눌리는 게 그 때문이었습니다

지금은 고정 키 지정을 없앴습니다. 멈춘 화면에서 무엇을 누를지는 전부 LLM이 정하고,
**LLM이 꺼져 있거나 판단에 실패하면 아무것도 누르지 않고 기다립니다.**
잘못 누르는 것보다 가만히 있는 편이 낫습니다 (그 상황은 로그에 남습니다).

한 번 누른 뒤에는 **그 키가 먹었는지 확인될 때까지 다시 누르지 않습니다.**
예전에는 1.4초만 지나면 또 눌러서 방금 고른 것이 뒤집히곤 했습니다.

ESC는 어떤 경우에도 나가지 않습니다 — 모델이 고를 수 있는 목록에 없고,
브릿지 화이트리스트에서도 빠져 있습니다. 애초에 모델은 키를 고르지 않습니다:
**항목 이름만 말하고, 키는 코드가 만듭니다.**

## 레벨업만 LLM에게 (선택)

구조는 이렇게 나뉩니다:

```
화면 인식(마더) ─┬─ 플레이 중  → 초파리 뇌 → WASD
                 ├─ 레벨업     → LLM → 어느 카드
                 └─ 메뉴/사망  → 지정한 키
```

둘이 동시에 도는 게 아니라 **화면 상태로 갈래가 갈립니다.** 레벨업은 게임이 멈춰 있어서
LLM이 몇 초 걸려도 되고, 아이템 조합은 학습으로 배우려면 수백 판이 필요한데 LLM은 그냥 압니다.
움직임은 계속 초파리 뇌가 하므로 반사 루프는 영향받지 않습니다.

쓰려면 [Ollama](https://ollama.com)를 설치하고 **이미지를 읽을 수 있는 모델**을 받으세요
(카드에 뭐가 떴는지 봐야 합니다). 그다음 페이지에서 `모델 목록`을 눌러 고르면 됩니다.
브라우저가 Ollama를 직접 부르면 CORS 설정이 필요해서, 브릿지가 대신 호출합니다.

### 어떤 모델을 쓰나 — 직접 돌려본 결과

```
ollama pull gemma3:12b
```

`gemma3:12b` 하나만 씁니다. 여러 개 받아봤지만 나머지는 전부 못 썼습니다:

| 모델 | 결과 |
|---|---|
| **gemma3:12b** | 화면 종류 3/3 정답, 카드 글씨도 읽음. 웜 약 5초 · VRAM 7.5GB (전부 GPU) |
| llama3.2-vision:11b | Ollama가 `mllama` 아키텍처를 지원하지 않아 **로드 자체가 안 됨** |
| qwen3-vl:8b | thinking 모델. 답이 `response`가 아니라 `thinking`으로 빠지고 한도에 걸려 **빈 응답** |
| qwen2.5vl:7b | 동작은 하나 쓰지 않기로 함 |

VRAM이 모자라면 `gemma3:4b`(약 3.3GB)로 내릴 수 있습니다. 화면 종류 구분은 되겠지만
카드에 적힌 작은 글씨를 읽는 정확도는 확인해봐야 합니다.

**`100% GPU`인지가 중요합니다.** VRAM이 모자라면 Ollama가 일부를 CPU로 넘기는데
그러면 5초짜리가 30초로 늘어납니다. 확인:

```
curl http://localhost:11434/api/ps
```

`size`와 `size_vram`이 같으면 전부 GPU에 올라간 것입니다.

### Ollama가 다른 PC에 있을 때

주소만 바꾸면 됩니다. 소스는 건드릴 것이 없습니다.

```
python bot/bridge.py --ollama http://192.168.0.50:11434
```

LLM이 실패하거나 응답이 이상하면 **지정한 키로 자동으로 떨어집니다.** 봇이 멈추지는 않습니다.
그리고 판마다 "무엇을 골랐고 몇 분 살았는지"를 기록해서 다음 판단에 같이 넘깁니다 — 이게 장기기억 역할을 합니다.

## 화면 판별도 LLM에게 (자동 학습)

레벨업 판단을 LLM에게 넘기려면 **먼저 "지금이 레벨업이다"를 알아야** 합니다.
원래 이건 LLM이 아니라 브라우저의 썸네일 비교가 했고, 그 비교는 사람이 2단계에서
직접 가르쳐준 샘플이 있어야만 작동했습니다. 아무것도 안 가르치면 움직임만 보고
플레이/메뉴 둘 중 하나로 찍기 때문에 **레벨업이 영영 나오지 않고**, 그래서 위의
카드 선택 코드도 영영 돌지 않았습니다.

`화면 종류도 LLM이 판별`을 켜면 그 구멍이 메워집니다:

```
움직임이 멎음 ──▶ 처음 보는 화면? ──▶ LLM에게 "이게 무슨 화면이냐" ──▶ 그 화면을 기억
                        │ 아니오                                              │
                        └────────── 로컬 썸네일 비교(0ms) ◀───────────────────┘
```

매 프레임 물을 수는 없습니다(한 번에 몇 초씩 걸립니다). 그런데 레벨업·메뉴·사망은
**전부 화면이 멈춥니다.** 멈춤은 움직임 수치로 공짜로 잡히니, 멈췄고 + 처음 보는 화면일
때만 한 번 묻습니다. 답이 오면 그 썸네일을 그대로 기억하므로 **같은 화면은 두 번 묻지
않습니다.** 결과적으로 LLM은 판마다 한 번도 안 불릴 수도 있습니다.

- 묻는 동안에는 메뉴 키를 누르지 않습니다 (엉뚱한 화면에서 엔터가 나가지 않게)
- 묻는 사이 화면이 넘어갔으면 그 답은 버립니다 (지난 화면의 답을 지금 화면에 붙이지 않게)
- 실패하면 8초 뒤에 다시 묻습니다. 그동안 봇은 평소대로 돕니다

## 멈춘 화면은 LLM이 — 그리고 한국어로 답하게

`멈춘 화면을 LLM에게` 를 켜면 레벨업뿐 아니라 **시작메뉴와 결과화면까지** LLM이 맡습니다.
`몰리에게 시킬 일` 칸에 한국어로 적어두면 그걸 기준으로 고릅니다.

```
몰리에게 시킬 일: 게임 시작해서 최대한 오래 살아남아라. 죽으면 바로 다시 시작해.
```

사람이 읽는 설명(`why`)은 한국어로 받고, 기계가 읽는 값은 영어 그대로 둡니다.
로그를 읽을 수 없으면 무엇이 잘못됐는지 확인할 방법이 없기 때문입니다.

### 왜 두 번 나눠 묻나

한 번에 "화면 보고 알아서 키 눌러"라고 시켰더니 형편없었습니다. 실측한 실패 지점이 분명했습니다:

| 물어본 것 | 정확도 |
|---|---|
| 화면에 무슨 항목이 있나 | 7/7 |
| 세로 배치인가 가로 배치인가 | 7/7 |
| 지금 뭐가 선택돼 있나 | 6/7 |
| **그래서 뭘 골라야 하나** | **2/7** |

**보는 건 잘하는데, 보면서 동시에 판단하는 걸 못합니다.** 그래서 쪼갰습니다.

```
1) 그림을 보고  → 항목 목록 · 배치 · 지금 선택된 것      (인식)
2) 글자만 보고  → 그중 지시를 수행하는 건 무엇인가        (판단)
3) 코드         → 거기까지 방향키를 몇 번 누를지          (계산)
```

2단계에는 **이미지를 주지 않습니다.** 목록만 주면 8/8로 맞힙니다
("도전과제를 확인해라" → `COLLECTION` 까지 이유를 대며 맞힙니다).
3단계 뺄셈은 코드가 합니다 — 모델에게 "몇 칸 내려가라"를 시키면 자주 틀립니다.

이렇게 나눈 뒤 전체 정확도가 **2/7 → 6/7** 이 됐습니다. 한 번 도는 데 6~14초 걸리지만
이 화면들은 게임이 멈춰 있어서 상관없습니다.

남은 1개의 실패는 "지금 선택된 게 두 번째 항목인데 첫 번째라고 읽는" 경우입니다.
이때는 0칸 이동으로 계산돼 엉뚱한 항목에 엔터가 갑니다. 다만 그 화면도 어차피 넘어가고,
다음 화면에서 지시대로 다시 고르므로 한 단계 낭비될 뿐 갇히지는 않습니다.

### 카드와 버튼은 갈라서 읽습니다

한 목록에 카드와 새로고침·건너뛰기·삭제를 섞어 읽히면 둘 다 흐려집니다.
그리고 더 나쁜 건, **방향키 계산이 어긋납니다** — 목록의 3번째가 카드인지 버튼인지에 따라
`아래 두 번`이 가리키는 곳이 달라지는데, 게임에서 커서가 버튼까지 같은 줄로 도는지
확인할 방법이 없었습니다.

지금은 카드만 `options` 로 읽고, 버튼은 `buttons` 라는 별개 항목으로 받습니다.
고르는 것도 카드 중에서만 합니다. 카드는 세로로 쌓여 있으니 방향키는 위/아래뿐입니다.

같은 이미지로 3회씩 재본 결과:

| | 카드 정답 | options 에 섞인 버튼 | 시간 |
|---|---|---|---|
| 예전 (한 목록) | 4/4 | **3.0개** | 7.4초 |
| 지금 (갈라서) | 4/4 | **0개** | 9.3초 |

버튼은 `buttons: ["Reroll","Skip","Banish"]` 로 따로 잡힙니다.
설명줄(`descs`)도 같이 읽어서 고를 때 근거로 쓰고, 읽은 기록에도 남깁니다 —
`Garlic (Damages nearby enemies)` 처럼 보이므로 잘못 읽으면 바로 드러납니다.
설명을 같이 읽느라 2초쯤 더 걸리지만, 레벨업은 게임이 멈춰 있어서 상관없습니다.

**주의**: 위 수치는 제가 그린 깨끗한 글씨 기준이라 카드 정답은 원래 4/4 였습니다.
실제 게임 폰트에서 이름을 더 잘 읽는지는 아직 증명되지 않았습니다 —
`레벨업에서 읽은 것` 기록을 보고 판단해야 합니다.

### 새로고침·건너뛰기·삭제는 아직 고르지 않습니다

지금은 카드만 고릅니다. 버튼은 읽어서 기록에 남기지만 선택 대상이 아닙니다.
게임에서 커서가 버튼까지 어떻게 도는지 확인된 뒤에 붙이는 편이 안전합니다.

### 여기까지 오게 된 경위

레벨업은 원래 "몇 번째 카드를 고를래?"를 **한 번에** 물었습니다. 그때 `why` 에는 옳은
이름을 써놓고 번호는 엉뚱한 걸 내서, **추론과 다른 아이템을 고르는** 일이 생겼습니다.
그래서 메뉴와 같은 2단계(보고 → 고르고 → 코드가 방향키 계산)로 바꿨고, 그 김에
버튼까지 한 목록에 넣었다가 위의 문제를 만났습니다.

로그에 `[Garlic → Runetracer · down down enter]` 처럼 어디서 어디로 갔는지 남으니,
고른 것과 누른 게 어긋나면 바로 보입니다.

### 판이 끝났다는 판단은 보류했다가 확정합니다

부활 화면을 사망으로 잘못 읽으면 그 순간 판이 끝나버립니다. 그런데 실제로는 부활해서
이어지므로, **한 판이 둘로 쪼개져 기록에 남습니다.** 생존 시간은 토막나고 피격 수도 나뉘어
통계가 전부 어긋납니다.

화면 판별을 더 정확하게 만드는 것으로는 부족합니다 — 언젠가 또 틀립니다.
그래서 끝났다는 판단을 **보류**로 두고, 플레이가 15초 안에 돌아오면 없던 일로 합니다.

| 화면 | 처리 |
|---|---|
| `사망` | 보류만 해둔다 (부활로 이어질 수 있음) |
| `부활` | 보류를 취소한다 — 이어지는 판이다 |
| `시작메뉴` | 바로 확정한다 (되돌릴 여지가 없음) |
| 보류한 채 15초 경과 | 확정한다 |
| 플레이 복귀 (15초 이내) | 취소하고 같은 판을 계속 |

생존 시간은 **끝났다고 본 그 시각**으로 계산합니다 — 보류하는 동안 흐른 시간은
생존 시간이 아니기 때문입니다.

화면 순서를 넣어 돌려본 결과 6/6 입니다:

```
play120 → dead3(오인) → play90 → dead5 → menu   ->  1판 213초   (쪼개지지 않음)
play100 → dead25       → play60 → menu          ->  2판 100/60초 (제대로 나뉨)
play60  → levelup10    → play60 → dead → menu   ->  1판 130초   (레벨업은 안 끊음)
```

### "날개를 골랐다" — 예시를 베끼고 있었습니다

카드를 못 읽으면 엉뚱한 아이템을 골랐다고 답하는 일이 있었습니다. 원인은 프롬프트였습니다.
답의 형식을 알려주려고 쓴 예시에 **실제로 있을 법한 이름**을 넣어뒀습니다:

```
{"options": ["Garlic", "Wings"], "selected": "Garlic", ...}
```

읽지 못하면 이걸 그대로 베껴 옵니다. 그래서 **Wings(날개)** 가 나왔습니다.
예시를 자리표시자로 바꾸고, 그래도 베껴 오면 코드가 걸러냅니다.

```
{"options": ["<name on card 1>", "<name on card 2>"], ...}
   -> 이런 답이 오면 "카드를 못 읽은 것"으로 처리하고 아무것도 누르지 않습니다
```

못 읽었으면 못 읽었다고 나와야 합니다. 그럴듯한 이름이 들어오면 그게 진짜인 줄 알고 눌러버립니다.

### 지어낸 이름은 두 번 읽혀서 잡습니다

"마나의 노래"를 "슈퍼 소울"로 읽는 건 **글자를 잘못 본 게 아닙니다** — 겹치는 글자가 없습니다.
못 읽으니까 그럴듯한 이름을 지어내는 것이고, 앞의 "날개(Wings)" 와 같은 병입니다.

한글 자체는 문제가 아닙니다. 깨끗한 한글 화면으로 재보면 `마나의 노래 / 성서 / 마늘 / 시금치`
를 4/4 그대로 읽습니다. 실제 게임 폰트·반투명 배경에서만 무너집니다.

읽기를 더 잘하게 만들 수단이 마땅치 않으므로, **틀렸을 때 들키게** 만들었습니다.
같은 화면을 두 번 읽혀 서로 대조합니다 — 지어낸 이름은 매번 달라지고, 진짜로 읽은 이름은
그대로입니다. 게임이 멈춰 있는 화면이라 한 번 더 물어도 됩니다.

```
읽을 수 있는 화면
  1차: 마나의 노래 / 성서 / 마늘 / 시금치
  2차: 마나의 노래 / 성서 / 마늘 / 시급치      -> 한 글자 차이, 제대로 읽은 것

읽을 수 없는 화면
  1차: 에스카 / 에스카 / 에스카 / 에스카
  2차: 피의 깃털 / 가구 / 고통 / 피갈           -> 딴판, 지어낸 것 -> 누르지 않음
```

글자가 똑같기를 요구하면 `시금치 / 시급치` 같은 한 글자 흔들림에도 막혀서, **얼마나 닮았는지**로
비교합니다(편집 거리, 0.5 미만이면 못 읽은 것). 실제 사례 10건으로 확인했습니다:

| 1차 vs 2차 | 닮음 | 판정 |
|---|---|---|
| 시금치 / 시급치 | 0.67 | 통과 |
| King Bible / King Bibel | 0.80 | 통과 |
| **마나의 노래 / 슈퍼 소울** | **0.17** | **막음** |
| 에스카 / 피의 깃털 | 0.00 | 막음 |
| 마늘 / 마법봉 | 0.33 | 막음 |

못 읽은 카드가 하나라도 있으면 **아무것도 누르지 않고 기다립니다.** 커서가 몇 칸 움직여야
하는지도 믿을 수 없기 때문입니다. 그리고 두 판독이 모두 기록에 남아서, 무엇을 어떻게
잘못 읽었는지 눈으로 볼 수 있습니다.

프롬프트에도 못을 박았습니다 — 한글이면 한글 그대로 옮기고, 번역·음차하지 말고,
**읽을 수 없으면 아는 아이템 이름으로 대신 채우지 말고 `?` 라고 답하라**고.

### 사진 한 장으로 바로 시험할 수 있습니다

게임을 돌리면서 고치려면 한 번 확인하는 데 한 판이 걸립니다.
`레벨업에서 읽은 것` 에 **사진으로 시험** 버튼을 뒀습니다. 레벨업 화면을 캡처해서
파일로 넣거나 **Ctrl+V 로 붙여넣으면** 됩니다. 게임에 보내는 것과 같은 크기·품질로 맞춰
같은 프롬프트를 태우므로, 실제로 무엇을 읽는지 그대로 나옵니다.

```
17:30:01 사진 [1280x720] 카드 4장: Whip (Attacks horizontally...) /
         Magic Wand (Fires at the nearest enemy.) / Pummarola (...) / Clover (...)
         · 선택돼 있던 것: Magic Wand · 누름: enter · 버튼: Reroll, Skip, Banish
```

### 레벨업에서는 목표를 지시로 받지 않습니다

`이번 판 목표` 는 메뉴에서 무엇을 누를지 정하는 기준입니다. 그런데 그게 레벨업 프롬프트에도
그대로 지시로 들어가 있었습니다. "죽으면 바로 다시 시작해라" 같은 문장이 **카드를 고르는
자리에서** 재시작을 떠올리게 만듭니다.

지금은 레벨업에서만 문구를 바꿔 넣습니다 — 목표는 배경으로만 주고,
**여기서 수행할 지시가 아니며 재시작·종료를 뜻하지 않는다**고 못박습니다.
메뉴·결과 화면에서는 예전처럼 지시로 그대로 씁니다.

### 캐시 때문에 막히지 않게 했습니다

소스를 고쳤는데 브라우저가 옛 `index.html` 을 들고 있으면, JS 는 새것인데 HTML 은 옛것이라
있어야 할 요소가 없어서 터집니다. 실제로 한 번 이렇게 막혔습니다.
nginx가 `Cache-Control: no-store` 를 주도록 설정을 붙였습니다 (`docker/nginx-nocache.conf`).
매번 Ctrl+F5 를 기억하지 않아도 됩니다.

### 무엇을 읽었는지 남깁니다

카드 이름을 잘못 읽으면 엉뚱한 걸 고릅니다. 그런데 **무엇을 읽었는지가 안 남으면 고칠 방법이 없습니다.**
`레벨업에서 읽은 것` 에 최근 12번이 쌓입니다 — 판을 넘겨도 남습니다.

```
14:22:07 [1280x720 화면전체] 읽음: Garlic / King Bible / Runetracer / Spinach / Reroll
         · 선택돼 있던 것: Garlic · 누름: down enter
　마늘은 이미 있으니 관통 무기를 하나 챙기는 편이 낫습니다.
```

굵게 표시된 것이 고른 항목입니다. 실제 카드와 다르게 읽고 있으면 여기서 바로 보입니다.
하나도 못 읽은 경우도 그대로 남습니다.

### 이미지 크기는 문제가 아니었습니다

"글씨가 작아서 못 읽나" 싶어 같은 화면을 세 가지로 잘라 재봤습니다.

| 보낸 것 | 카드 이름 | 옆 버튼 |
|---|---|---|
| 화면 전체 → 900 | 4/4 | 3/3 |
| 화면 전체 → 1280 | 4/4 | 3/3 |
| **카드 영역만 → 1280** | 4/4 | **0/3** |

1920x1080 을 900 으로 줄여 보내도 다 읽습니다. 오히려 **카드 영역을 좁게 지정하면
새로고침·건너뛰기·지우기가 크롭 밖으로 밀려나 아예 안 보입니다.** 크기보다 범위가 중요합니다.

그래서 `레벨업 카드 영역` 은 보통 지정하지 않는 편이 낫습니다. 지정해두면 경고가 한 번 뜹니다.
(깨끗한 합성 글씨로 잰 수치입니다. 실제 게임 폰트에서 잘못 읽는다면 크기가 아니라
글꼴·배경 비침 쪽이 원인이므로, 위 기록을 보고 다시 판단해야 합니다.)

### 화면이 확정되기 전에는 누르지 않습니다

레벨업이 막 떴는데 아직 "플레이 중"으로 읽히는 찰나가 있습니다. 그때 키가 나가면
추론도 하기 전에 카드가 골라져 버립니다. 그래서 **같은 판정이 450ms 이어져야** 키를 누릅니다
(`SETTLE_MS`). 잡고 있던 이동키를 놓는 것만은 기다리지 않고 즉시 합니다 — 메뉴가 떴는데
계속 움직이고 있으면 곤란하니까요. 상태 표시에 `확인 중` 이 뜨는 동안이 그 구간입니다.

### 경험치 바를 지정해야 "얻었다"는 신호가 생깁니다

젬 항목만으로는 **무언가를 얻었다는 신호가 없습니다.** `fieldFeatures` 가 매 프레임
`gem[d] /= maxG` 로 정규화하기 때문에, 그 값은 젬의 양이 아니라 **방향 분포의 모양**입니다.
게다가 젬을 먹으면 그게 사라져서 분포가 흔들립니다 — 잘한 일이 감점으로 보일 수도 있습니다.

경험치 바는 그 구멍을 정확히 메웁니다. **올라갔다면 확실히 먹은 것입니다.**
LLM은 쓰지 않습니다 — 매 프레임 필요한 값이라 몇 초씩 걸리는 수단으로는 안 됩니다.
체력바와 같은 방식으로 픽셀에서 바로 읽습니다.

이제 **지정하지 않아도 읽습니다.** 뱀서는 화면 맨 위 전체 폭이 경험치 바라서, 게임 영역
맨 위 네 줄(분석 화면 기준, 원본 약 16픽셀) 중 한 줄을 골라 읽습니다. 게임 화면 위에
**초록 가로선**으로 어느 줄을 읽는지, 그 위의 작은 막대로 어디까지 찼다고 읽었는지 보입니다.
상태 칸에는 `경험치 37% (맨 위 한 줄)` 처럼 나옵니다.

게임 영역이 게임 화면에 딱 맞지 않아 선이 바 위에 있지 않으면, 직접 지정할 수 있습니다:

```
화면 설정 → 영역 지정 → [경험치 바 지정] → 화면 맨 위 가로 바를 드래그
```

지정했을 때도 그 사각형의 **가운데 한 줄만** 읽습니다. 두께 전체를 평균하면 테두리와
"LV" 글씨가 섞입니다.

경험치를 읽으면 보상에 `경험치` 항이 생기고, 판 기록의 보상 구성에도 나타납니다.
못 읽으면 **보상 진단이 "경험치 항이 0 — 무언가를 얻었다는 신호가 아예 없습니다"** 라고
경고합니다. 경험치를 읽는 동안에는 젬 근접 항의 비중을 0.2 → 0.05 로 낮춥니다
(약한 대용품이었으니 진짜 신호가 생기면 물러나야 합니다).

### 색이 아니라 채워진 위치로 읽습니다

처음에는 체력바처럼 "지정할 때 뽑아둔 기준색과 비슷한 픽셀"을 셌습니다. 그런데
**레벨업하면 바가 번쩍여서** 그 색과 안 맞게 되고, 그 순간 0% 로 읽힙니다.

그래서 경험치 바만은 다르게 읽습니다. 특정 색을 찾지 않고 **왼쪽 끝부터 "켜진 칸"이 어디까지
이어지는지**를 봅니다. 켜진 칸은 색이 선명하거나 밝은 칸이고, 빈 트랙은 어둡고 흐립니다.
바 색이 파랑이든 초록이든 상관없고, 레벨업 때 바가 하얗게 번쩍여도 밝으니 켜진 칸입니다.

예전에는 바의 양쪽 끝 색을 기준으로 삼았는데, 오른쪽 끝에 **"LV 12" 글씨**가 있으면 기준이
흐트러져 **0% 를 100% 로 읽었습니다.** 지금 방식은 왼쪽에서 오다 빈 곳에서 멈추므로 글씨에
닿지 않습니다.

합성 화면으로 잰 값:

| 실제 | 읽은 값 |
|---|---|
| 37% / 5% / 80% | 37.1% / 5.0% / 80.0% |
| 레벨업 순간 바 전체가 하얗게 번쩍임 | 100% |
| 레벨업 직후 0% ("LV" 글씨 있음) | 0% (예전 방식은 100%) |
| 알록달록한 파란 맵 바로 위의 바 42% | 42.1% |

그래도 **엉뚱한 줄을 읽으면** 값이 안 변합니다. 45초 내내 같은 값이면 로그로 알려줍니다.

### 피격은 캐릭터가 빨개지는 걸로 봅니다

체력바는 캐릭터를 따라다녀서 위치가 계속 바뀌고, 지정해두지 않으면 아예 못 읽습니다.
그런데 캐릭터는 **항상 화면 정중앙**에 있고 맞으면 빨갛게 번쩍입니다. 그걸 씁니다.

중앙 ±6픽셀의 "빨강이 다른 두 색보다 얼마나 앞서는가"를 재고, 평소 값(EMA)보다
`0.1` 이상 뛰면 피격으로 봅니다. 번쩍이는 동안에는 평소 값을 갱신하지 않습니다 —
그러면 기준이 같이 끌려 올라가 피격이 묻힙니다. 보상에는 붉어지기 시작한 **순간에만**
한 번 반영됩니다(번쩍이는 내내가 아니라).

화면의 `중앙빨강 0.031 (평소 0.028, +0.1 넘으면 피격)` 표시로 임계값이 맞는지 볼 수 있습니다.
체력바를 지정해뒀다면 그쪽이 우선이고, 이건 없을 때의 대비책입니다.

### 보상 상자 · 부활, 그리고 직접 물어보기

화면 종류에 `보상 상자`와 `부활`이 추가됐습니다. 특히 부활은 **사망과 구분해야** 합니다 —
같은 판을 이어갈 수 있는데 죽은 걸로 처리하면 판이 거기서 끝나버립니다.
`YOU DIED` 글자가 아니라 **무엇을 제안하고 있는지**로 가릅니다:

| 화면에 있는 것 | 판정 |
|---|---|
| Revive / Continue — 같은 판을 이어감 | `revive` |
| Retry / Restart / Main Menu — 새 판 | `dead` |
| 생존시간·처치수·골드 결과표 | `dead` |

자동 판별은 "멈췄고 + 처음 보는 화면"일 때만 돕니다. 보상 상자처럼 잠깐 스쳐가거나
사람이 먼저 확인하고 싶은 화면은 그 조건에 안 걸립니다. 그래서 **직접 물어보는 버튼**을 뒀습니다:

```
[지금 화면이 뭔지 물어보기]  →  "보상 상자 라고 합니다 (5.4초) — 상자가 열려 있고..."
[이 답으로 기억시키기]       →  다음부터는 묻지 않고 즉시 알아봄
```

답이 틀리면 기억시키지 말고 2단계 버튼으로 직접 가르치면 됩니다.

### 반대로, 사람이 알려주기

물어봤는데 못 맞히면 그걸로 끝이었습니다. 방향이 한쪽뿐이었기 때문입니다.
`몰리에게 알려주기` 칸에 **말로 적으면** 됩니다.

```
이건 보물상자 연 화면이야. 아무 키나 누르면 넘어가
  → "보상 상자" 화면으로 기억했습니다
```

두 가지가 일어납니다:

1. 적어준 말이 아는 화면 중 무엇인지 **글자만으로** 물어 정합니다
   (그림을 같이 주면 화면에 끌려가 엉뚱하게 답하는 게 이미 확인됐습니다)
2. **지금 보이는 화면 사진에 그 메모를 붙여서 기억합니다**

### 메모는 그 화면에만 붙습니다

처음에는 메모를 전역 목록으로 들고 다녔는데, 그러면 **관계없는 화면을 볼 때도 메모가
전부 따라 들어갑니다.** 쌓일수록 모든 판단이 그 말들에 끌려갑니다. 그래서 바꿨습니다.

```
기억 = { 화면 축소 이미지,  그 화면에 대한 메모 }
```

화면이 매칭되면 **그 샘플에 붙은 메모만** 프롬프트에 들어갑니다. 보상 상자에 적어둔 말이
레벨업 화면을 판단할 때 끼어들지 않습니다. 화면이 늘어나도 서로 섞이지 않습니다.

화면 공유가 꺼져 있으면 붙일 화면이 없으므로 거절합니다.

### 화면 종류는 말하면 늘어납니다

처음에는 화면 종류가 여섯 개로 고정이었습니다. 그래서 "이건 카드 선택 화면이야" 라고 해도
그 여섯 개 중 하나에 억지로 밀어넣었습니다. 게임마다 화면은 다르고, 뱀서만 해도 여섯 개로는
모자랍니다. 그래서 **아는 종류에 없으면 그 자리에서 새로 만듭니다.**

```
"이건 캐릭터 고르는 화면이야. 좌우로 움직여서 고르면 돼"
  → "캐릭터 선택" 이라는 화면 종류를 새로 만들었습니다
```

만들어진 종류는 **가르치기 버튼**(✎ 표시)과 **화면별 누를 키** 목록에 함께 올라가고,
`화면 판별` 프롬프트에도 이름과 그 화면에 붙여둔 메모가 같이 들어갑니다 —
모델이 알 리 없는 종류이므로 설명을 줘야 알아봅니다.

키는 영문 소문자로만 받고(프롬프트에 들어가는 값이라), 한국어 이름은 버튼에 표시됩니다.
`지정한 것 전부 지우기` 를 누르면 만들어둔 종류도 함께 사라집니다 — 기억이 없으면
종류만 남아봐야 쓸모가 없기 때문입니다.

## 목표는 한 판짜리입니다

`이번 판에 해야 할 목표` 에 적은 말은 멈춘 화면(시작메뉴 · 레벨업 · 결과)의 판단 기준이 됩니다.
판이 끝나면 몰리가 **이번 판에서 얻은 것**을 정리해 보여주고, 목표는 거기서 놓습니다.

```
이번 판에서 얻은 것
생존 8분 12초 · 피격 23회 (분당 2.8) · 가져간 것: Garlic, Wings, Spinach
목표였던 것: 마늘 위주로 가서 10분 버텨
10분을 채우지 못했지만 마늘 중심으로는 잘 갔습니다.
```

마지막 한 줄은 목표와 실제 결과를 대조해 받아온 것입니다(글자만 보내는 짧은 호출).

`목적 계속 반복` 을 켜두면 목표를 그대로 두고 다음 판도 같은 목표로 돕니다.
꺼져 있으면 목표를 비우고, 그 뒤로는 목표 없이 쭉 진행합니다.

## 화면이 복잡해서 접어뒀습니다

자주 건드리는 것만 펴져 있습니다.

```
조작 버튼 · 인식 표시 / 로그 기록
■ 이번 판에 해야 할 목표      ← 목표 · 목적 계속 반복 · 판 결과
  상태 9칸
■ 추론 로그
▸ LLM — 멈춘 화면 판단
▸ 화면 설정 — 영역 지정 · 화면 가르치기 · 누를 키
▸ 인식 민감도와 성향
▸ 판 기록과 통계
```

### LLM이 아무 키나 누르지는 못합니다

고를 수 있는 키는 `enter · space · 방향키` 뿐입니다. 모델이 뭐라고 답하든 그 밖은 걸러집니다.
그리고 애초에 모델은 키를 고르지 않습니다 — **항목 이름만 말하고, 키는 코드가 만듭니다.**
목록에 없는 이름을 대면 아무것도 누르지 않고 지정해둔 키로 떨어집니다.
ESC는 어느 단계에도 없고 브릿지 화이트리스트에서도 빠져 있습니다.

## 몰리가 정말 보고 움직이는지 — 블라인드 테스트

"화면을 보고 움직이는 건지, 그냥 무작위로 움직이는 건지" 는 겉으로 봐서는 알 수 없습니다.
그래서 두 가지 시험을 둡니다.

### 1. 반응 검사 (게임 없이 즉시)

"적이 오른쪽에 몰렸다", "젬이 왼쪽에 있다" 같은 **인공 상황을 실제 판단 함수에 그대로 넣어**
고른 방향이 말이 되는지 봅니다. 같은 상황을 5번씩 넣어 **매번 같은 답**이 나오는지도 봅니다 —
무작위라면 흔들립니다. 학습 비중 슬라이더 값 그대로 시험하므로, 0%면 규칙을, 100%면 학습한 뇌를 봅니다.

**처음 돌렸을 때 실제 버그가 나왔습니다:**

```
실패  적이 오른쪽에 몰림 → 위    (기대: 왼쪽)
실패  적이 왼쪽에 몰림   → 위    (기대: 오른쪽)
실패  적이 위쪽에 몰림   → 오른  (기대: 아래쪽)
통과  적이 아래쪽에 몰림 → 위    ← 운이 좋았을 뿐
```

적이 어느 쪽에 있든 **위로** 갔습니다. 규칙에 "적 쪽으로 가지 마라" 만 있고
"적 반대로 도망쳐라" 가 없어서, 적이 없는 방향들이 전부 동점이 됐고 — 동점이면 첫 번째인
`위` 가 뽑혔던 겁니다. 적의 무게중심 반대쪽에 점수를 더 주도록 고쳐서 **8/8** 이 됐습니다.

```
통과  적이 오른쪽에 몰림 → 왼
통과  적이 왼쪽에 몰림   → 오른
통과  적이 위쪽에 몰림   → 아래
통과  사방이 막히고 왼아래만 뚫림 → 왼아래
```

### 2. 블라인드 판 (실제 게임에서 비교)

반응 검사는 "상황에 맞게 고르는가" 까지만 알려줍니다. **그게 실제로 오래 살게 해주는지** 는 따로 봐야 합니다.

`블라인드 테스트` 메뉴에서 블라인드를 켜면, 그 판은 몰리가 **화면을 보지 않고** 돌아다닙니다
(한 방향을 0.4~1.5초 유지하다 무작위로 바꿈 — 매 프레임 바꾸면 제자리에서 떨기만 해서).
피격은 똑같이 세고, **학습은 하지 않습니다** — 눈 감고 한 행동으로 배우면 뇌가 망가집니다.

```
화면을 본 판 — 5판 · 평균 생존 6분 12초 · 분당 피격 2.1
블라인드 판  — 5판 · 평균 생존 2분 40초 · 분당 피격 5.8
본 판이 2.3배 오래 삽니다 — 화면을 보는 게 효과가 있습니다
```

`판마다 번갈아` 가 가장 공정합니다 — 같은 시간대, 같은 실력으로 비교되니까요.
양쪽 다 3판 이상 모여야 판정을 냅니다. 비슷하게 나오면 **지금은 봐도 도움이 안 되고 있다** 는 뜻입니다.

## 모니터링 — 한 화면에

시야·로그·레벨업에서 읽은 것을 보려고 메뉴를 계속 바꿔야 했습니다.
왼쪽 메뉴 맨 위의 **모니터링** 을 고르면 셋을 한 화면에 나란히 보여줍니다(기본으로 이게 열립니다).

```
┌────────────────────┬──────────────────┐
│ 몰리 시야           │ 추론 로그          │
│ (격자 + 8방향 점수) ├──────────────────┤
│                    │ 레벨업에서 읽은 것  │
└────────────────────┴──────────────────┘
```

모니터링에서는 긴 설명을 숨깁니다. 설명이 필요하면 각 메뉴를 따로 열면 됩니다.
마지막으로 보던 메뉴를 기억합니다.

## 영역에 이름 붙이기

화면의 한 부분을 드래그하고 **그게 무엇인지 적어두면**, LLM 이 그 화면을 볼 때
"그 위치에 그게 있다" 는 걸 알고 판단합니다. `화면 설정 → 영역 지정 → 이름 붙이기`.

- 이름을 모르겠으면 **LLM에게 뭔지 묻기** — 그 부분만 잘라 보내서 물어봅니다
- **보이는 화면** 을 정하면 그 화면일 때만 알려줍니다 (캐릭터 목록은 캐릭터 선택 화면에만 있으니까요)
- 게임 화면 위에 주황 점선으로 이름과 함께 그려집니다. 다른 화면용은 흐리게
- 몰리 시야에 "이 화면에서 LLM 에게 알려주는 영역" 이 나옵니다

LLM 에게는 **보내는 이미지 기준** 좌표로 바꿔서 알려줍니다. 레벨업 영역만 잘라 보낼 때는
그 안의 좌표로 바뀌고, 잘라낸 이미지 밖의 영역은 빠집니다:

```
The player has marked and named these regions of the image. ...
- "캐릭터 목록": x 0.10~0.60, y 0.30~0.80
- "경험치 바": x 0.00~1.00, y 0.00~0.04
```

화면 판별 프롬프트에는 전부 넣고, 어느 화면의 영역인지를 붙입니다
(`"캐릭터 목록" (only on the character_select screen)`). 그 영역이 보이면 그 화면이라는 단서가 됩니다.

## 메뉴에서 늘 s s s s → 엔터만 누르던 문제

맵 선택에서 넘어가지 못했습니다. 원인은 두 가지였습니다.

1. **목표가 "게임을 시작해" 라서 LLM이 확인·시작 버튼을 골랐습니다.** 목록 맨 끝(다섯 번째)이라
   커서에서 아래로 네 칸 = `s s s s`. 그런데 그 버튼은 커서를 옮겨서 가는 곳이 아닙니다.
   아래로 누르면 맵 목록 안에서만 움직이고, 엉뚱한 맵에서 엔터가 눌렸습니다.
2. **옮기고 확인하지 않았습니다.** 커서 위치를 한 번 읽고 이동 키와 엔터를 한꺼번에 눌렀습니다.
   그리고 다음에 같은 화면을 보면 **또 똑같이** 눌렀습니다.

지금은 이렇게 합니다.

- **지금 커서가 어디 있는지 LLM에게 알려주고**, "엔터를 누르면 그게 골라지고 넘어간다.
  특정한 캐릭터·맵을 요청받은 게 아니면 지금 선택된 것을 그대로 고르라" 고 안내합니다.
  보통은 움직이지 않고 **엔터 한 번**으로 끝납니다.
- 옮겨야 하면 **옮긴 뒤 화면을 다시 읽어서** 커서가 목표 위에 있을 때만 엔터를 누릅니다
  (최대 3번). 못 닿으면 엔터를 누르지 않습니다 — 엉뚱한 칸이 확정되지 않습니다.
- **같은 화면에서 해본 것을 기억합니다.** 다시 물을 때 "이미 X로 가서 엔터를 눌렀는데 안 넘어갔다"
  를 알려주고, 같은 곳으로 두 번 가봤으면 모델이 뭐라 하든 지금 선택된 곳에서 엔터만 누릅니다.
  그것도 안 되면 **"이 화면에서 막혔습니다"** 를 한 번 알리고 20초씩 쉬며 계속 두드리지 않습니다.
  플레이로 넘어가면 기억을 지웁니다.

로그에는 무엇을 보고 어떻게 옮겼는지가 남습니다:

```
메뉴 Mad Forest [이미 Mad Forest 위 → 엔터] ...
메뉴 "Confirm" 로 못 옮겨서 엔터를 누르지 않았습니다 [Mad Forest에서 s s s s → Gallo Tower에서 s → 커서가 그대로 Gallo Tower ...]
메뉴 Gallo Tower [이미 Gallo Tower 위 → 엔터] "Confirm" 로 2번 가봤지만 넘어가지 않아서, 지금 선택된 "Gallo Tower" 에서 엔터만 누릅니다
```

가짜 맵 선택 화면(확인 버튼은 이동으로 못 감)과 대본대로 답하는 가짜 LLM으로 돌려봤습니다:

| 경우 | 누른 키 | 결과 |
|---|---|---|
| 지금 선택된 맵을 고름 | `엔터` | 1번에 넘어감 |
| 계속 확인 버튼을 고집 (예전 증상) | `s×4, s` (엔터 없음) → `s` → `엔터` | 3번째에 넘어감 |
| 커서를 늘 첫 칸으로 잘못 읽음 | `s` → `s` → `엔터` | 3번째에 넘어감 |
| 무엇을 눌러도 안 넘어가는 화면 | `엔터` 두 번 | 멈추고 "막혔습니다" |

LLM이 한 번 읽는 데 몇 초 걸리므로, 옮겨야 할 때는 예전보다 느립니다.

## 레벨업 카드를 엉뚱하게 고르던 문제

메뉴는 "옮기고 → 다시 읽어 확인하고 → 엔터" 로 고쳤는데, **레벨업은 옛날 방식 그대로**였습니다.
커서가 몇 번째 카드에 있는지 LLM 이 한 번 읽고, 이동 키와 엔터를 한꺼번에 눌렀습니다. 그래서:

- 커서 위치를 한 칸만 잘못 읽어도 다른 카드가 확정됐고
- 첫 입력이 커서를 잡기만 하고 움직이지 않는 화면이면 **매번 한 칸 앞 카드**가 확정됐습니다

이제 레벨업도 메뉴와 같은 길입니다. 옮길 때마다 카드를 다시 읽어 커서가 고른 카드 위에 섰는지 보고,
그때만 엔터를 누릅니다. 눌렀는데 그대로면 한 번은 더 눌러 보고, 그래도 그대로면 엔터를 누르지 않습니다.
이미 그 카드 위면 다시 읽지 않고 엔터만 누릅니다. 옮길 때마다 한 번 더 읽어서 몇 초씩 더 걸립니다.

가짜 게임(카드 4장)으로 돌려본 결과:

| 상황 | 예전 방식 | 지금 |
|---|---|---|
| 첫 입력은 커서만 잡는 게임, 3번째 카드 | 2번째 확정 (틀림) | 3번째 (`s s` → 다시 읽기 → `s` → 엔터) |
| 커서가 2번째인데 1번째라고 읽음, 3번째 카드 | 4번째 확정 (틀림) | 3번째 (`s s` → 다시 읽기 → `w` → 엔터) |
| 보통 게임, 4번째 카드 | 4번째 | 4번째 |
| 이동 키가 안 먹음 | 1번째 확정 (틀림) | 엔터 안 누르고 로그로 알림 |

`레벨업 읽은 것` 기록과 폰 화면에 **커서가 어디 있다고 봤는지, 어떻게 옮겼는지, 화면 글자로 이름이 확인됐는지**가
같이 남습니다: `마나의 노래에서 s s → 시금치에서 s → 엔터`. 또 틀리면 이걸로 어디서 어긋났는지 보입니다.

## 카드에서 엔터 → "획득하기" 에서 한 번 더

지금 뱀서 레벨업은 **카드에서 엔터를 누르면 골라 두기만 하고**, 아래 **획득하기** 로 커서를 옮겨 엔터를
한 번 더 눌러야 확정됩니다. 예전에는 카드에서 엔터만 누르고 끝나서 화면이 그대로 멈춰 있었습니다.

이제 엔터 뒤에도 **같은 화면**이고 화면 글자(OCR)에 확정 버튼(`획득하기`, `확인`, `선택하기`, `CONFIRM` …)이
보이면 그리로 옮겨 한 번 더 누릅니다. 카드(세로)와 버튼(아래)은 배치가 섞여 있어서 **화면 글자의 위치**로
방향을 잡습니다: 커서가 있는 글자에서 "획득하기" 글자 쪽으로, 그 사이에 있는 항목 수만큼 한 번에 누르고,
다시 읽어 버튼 위에 섰을 때만 엔터. 캐릭터 선택처럼 "고르고 → 확인" 하는 화면과 폰 지시에도 같이 씁니다.

- 카드 엔터로 바로 확정되는 화면이면(다음 화면으로 넘어감) 아무것도 더 안 누릅니다 — 다음 화면의 "확인" 을
  잘못 누르지 않게, 첫 엔터 직전 화면과 거의 같을 때만 확정 단계를 합니다.
- 확정 버튼이 안 보이면 더 누르지 않습니다.

가짜 레벨업 화면(카드 4장, 그 아래 획득하기, 맨 아래 새로고침·건너뛰기·삭제)으로 돌려본 결과, 네 장 중
어느 카드든 그 카드로 확정됐고, 화면 읽기는 한 번에 2~3번이었습니다 (한 칸씩 읽을 때는 5번).

## 공략 (진화 조합)

`game/knowledge/vs_evolutions.json` — 나무위키 "Vampire Survivors/아이템/진화 무기" 문서의 **조합식만** 옮긴 것
(147개, 본편 + DLC). 설명 글은 넣지 않았고 출처·라이선스(CC BY-NC-SA 2.0 KR)를 파일에 적어뒀습니다.

gemma3 는 뱀서 진화 조합을 잘 모르거나 지어냅니다. 그래서 레벨업 때 **지금 나온 카드와 이번 판에 고른 것**에
관련된 조합만 이름으로 정확히 찾아 고르기 프롬프트에 붙입니다 (RAG 비슷한 것):

```
- 시금치: 불의 지팡이 (최고 레벨) + 시금치 → 헬파이어 · 이미 가진 것: 불의 지팡이
- 검은 심장: 채찍 (최고 레벨) + 검은 심장 → 피눈물 · 이미 가진 것: 채찍
```

- 카드가 기본 무기인 조합은 늘, 카드가 재료로 쓰이는 조합은 **이미 가진 것과 이어질 때만** 붙입니다
  (검은 심장처럼 여러 조합에 쓰이는 재료를 다 늘어놓으면 너무 깁니다). 최대 12줄.
- 이름은 띄어쓰기·대소문자를 무시하고 맞춥니다. 한 글자 틀림은 6자 이상 이름에서만 봐줍니다 —
  `검은 심장` 과 `붉은 심장` 은 한 글자 차이지만 다른 아이템입니다.
- 쓴 공략 줄은 `레벨업 읽은 것` 기록에 `공략: …` 으로 남습니다.
- "이미 가진 것" 에는 이번 판에 레벨업에서 고른 것과 **고른 캐릭터의 시작 무기**가 들어갑니다 (아래).

### 잘못 읽은 카드 이름 바로잡기 (아이템 사전)

화면 글자를 같이 줘도 이름을 이상하게 읽었습니다. gemma3 는 작은 한글 게임 글씨가 흐릿하면 아는 단어로 채우고,
OCR 은 픽셀 글씨에서 한두 글자를 틀립니다 (`시금치` → `시급치`). 그리고 예전에는 "화면 글자에 있나" 만
확인했지 **이름을 고치지는 않았습니다.**

`game/knowledge/vs_items.json` — 나무위키 일반 무기·장신구·진화 무기 문서의 **이름만** 모은 사전(362개:
무기 183, 장신구 32, 진화 무기 147). 읽은 이름을 이 사전과 비교해 바로잡습니다:

1. 화면 글자 중 사전 이름과 아주 비슷한 줄 = 화면에 실제로 있는 카드 (`마늘 새로운!` 처럼 뒤에 붙은 말은 떼고 봅니다)
2. LLM 이 읽은 이름이 그중 하나로 이어지면 → 사전 철자로 (`시급치` → `시금치`, `마나의노래` → `마나의 노래`)
3. 엉뚱한 이름을 지어냈고 카드 장수가 같으면 → **같은 자리의 실제 카드** (`슈퍼 소울` → 그 자리의 `시금치`)
4. 화면 글자가 없으면 → 사전에서 가장 비슷한 이름. 두 후보가 비슷하게 맞으면 헷갈리니 안 고칩니다

비교는 **자모 단위**로 합니다 (`시금치` = ㅅㅣㄱㅡㅁㅊㅣ). 받침 하나 틀림이 음절로는 67% 인데 자모로는 86% 라서
한글 이름은 이렇게 비교해야 제대로 가깝게 나옵니다. 영어 이름(`Spinach` → `시금치`)도 봅니다.
`검은 심장` 과 `붉은 심장` 처럼 한 글자만 다른 아이템은 서로 바꾸지 않습니다.

고친 이름을 그다음 모든 곳 — 두 번 읽기 대조, 고르기, 공략 찾기, 커서 옮긴 뒤 다시 읽기, 이번 판에 고른 것 — 에
씁니다. 화면 글자로 카드가 다 확인되면 두 번 읽지 않습니다. `레벨업 읽은 것` 과 폰에
`이름 고침: 시급치 → 시금치 (화면 글자+사전)` 로 남습니다.

### 캐릭터·스테이지 목록

`game/knowledge/vs_characters.json` (209명: 일반·히든·DLC) 과 `vs_stages.json` (33개) — 나무위키 캐릭터·스테이지
문서에서 **이름, 시작 무기, 체력, 짧은 효과, 해금 조건, 스테이지 시간**만 옮겼습니다. 운용 팁 같은 글은 넣지 않았습니다.

- **메뉴에서 고를 때**: 항목이 아는 캐릭터·스테이지면 LLM 에게 사실을 같이 줍니다.
  목표가 "마늘 쓰는 캐릭터로" 면 `- 포 랏초: 캐릭터 · 시작 무기 마늘 · 체력 70 · 자석 +25%` 를 보고 고를 수 있습니다.
- **고른 캐릭터 기억**: 메뉴에서 엔터를 누르기 직전, 고르는 항목이 캐릭터 이름이거나 화면 글자에 캐릭터 이름이
  **딱 하나** 보이면 그 캐릭터를 기억합니다 (캐릭터 선택 화면은 초상화만 있고 옆 칸에 선택된 캐릭터 이름만 나옵니다).
  이름이 둘 이상 보이면 누군지 모르니 기억하지 않습니다. 새로 고를 때까지 판을 넘어도 유지하고, 폰 화면에도 보입니다.
- 그 캐릭터의 **시작 무기**를 레벨업 공략의 "이미 가진 것" 에 넣습니다. 포 랏초로 시작했으면 붉은 심장 카드에
  `마늘 (최고 레벨) + 붉은 심장 → 영혼 포식자 · 이미 가진 것: 마늘` 이 붙습니다.
- 짧은 이름("이멜다")은 정확히 같을 때만 알아봅니다. 한 글자 이름("포")은 다른 말과 겹쳐서 보지 않습니다.

## 레벨업 영역

`화면 설정 → 레벨업 영역 지정` 으로 레벨업 창 전체를 감싸주세요 —
**카드뿐 아니라 새로고침·건너뛰기·삭제 버튼까지.**

1. 카드를 읽을 때 그 부분만 크게 잘라 보냅니다 (화면 전체를 줄이는 것보다 글자가 큽니다)
2. 게임이 멈췄는지 볼 때 그 부분을 뺍니다 — 창이 뜨는 자리를 정확히 알게 됩니다
   (지정하지 않으면 가운데 원을 뺍니다)

**버그가 있었습니다**: 이 버튼을 눌러 드래그해도 저장이 안 됐습니다. 드래그 시작을
`게임/체력/경험치` 만 받고 레벨업 영역을 빠뜨렸기 때문입니다. 고쳤습니다.

## 캐릭터를 골랐는데 골랐다는 걸 모를 때

세 가지 원인이 겹쳐 있었습니다.

**1. 넘어갔는지를 화면 종류 이름으로만 봤습니다.**
캐릭터 선택 → 스테이지 선택은 둘 다 '메뉴' 라서 이름이 안 바뀝니다. 화면은 바뀌었는데도
"눌렀지만 화면이 그대로입니다" 가 떴습니다. 지금은 **누르기 직전 화면과 지금 화면을 직접 비교**합니다.
커서만 옮겨가는 정도(차이 0.004)는 넘어간 게 아니고, 다른 화면(차이 0.275)이면 넘어간 것입니다.

**2. 메뉴 이동을 방향키로 했습니다.**
게임 안 이동은 WASD 로 하고 있고 그건 잘 먹습니다. 방향키는 확장 키라서
NumLock 이 켜져 있으면 브릿지(pydirectinput)가 `0xE0` 을 한 번 더 보내는 경로를 탑니다.
게임에 따라 불안정합니다. **메뉴 이동도 WASD 가 기본**이고, `LLM → 메뉴 이동 키` 에서 방향키로 바꿀 수 있습니다.

**3. 캐릭터 선택은 격자인데 한 줄 목록으로 취급했습니다.**
한 줄에 4칸인 격자에서 0번 → 5번은 "오른쪽 5번" 이 아니라 **아래 1번 + 오른쪽 1번** 입니다.
화면을 읽을 때 격자인지, 한 줄에 몇 칸인지도 물어서 위아래와 좌우를 따로 셉니다.

```
0 -> 5  (4칸 격자) : s d
3 -> 12 (4칸 격자) : s s s a a a
```

로그에는 커서가 어디 있다고 봤는지가 남습니다: `[커서 안토니오 → 이멜다 · 4칸 격자]`.
그래도 안 넘어가면 이유를 짚어줍니다:
```
눌렀지만 화면이 그대로입니다 (화면 차이 0.000 — 키가 게임에 안 들어갔거나,
커서 위치를 잘못 읽었을 수 있습니다. 대상 창과 메뉴 이동 키 설정을 확인하세요)
```

## 폰으로 보기

PC 에서 돌리는 몰리를 폰에서 보고, 막혔으면 지시합니다. 폰이 키를 직접 누르지는 않습니다 —
지시를 받은 PC 탭이 화면을 보고 처리하고, 키는 거기서도 허용된 것만 나갑니다.

### 왜 페이지를 그냥 열면 안 되나

폰에서 게임 페이지 주소를 열면 **빈 페이지**가 뜹니다. 화면 공유, 시야, 로그, 판 기록은 전부
PC 브라우저 탭 안에만 있기 때문입니다. 그래서:

```
PC 탭 ──2초마다 상태·화면──▶ 브릿지 (이 PC 안, WebSocket) ◀──2초마다 가져감── 폰 (http://PC주소:8745)
```

화면(게임 화면·시야 그림)은 **폰이 실제로 보고 있을 때만** 보냅니다. 아무도 안 보면 글자 상태만 오갑니다.
폰 화면이 꺼지면 폰도 가져가기를 멈춥니다 (데이터·배터리).

### 켜기

```powershell
.\start.ps1 -Remote            # 또는: bot\.venv\Scripts\python.exe bot\bridge.py --remote
```

기본은 **꺼져 있습니다.** 켜면 브릿지가 이렇게 알려줍니다:

```
폰으로 보기 : http://192.168.219.100:8745
              보기 + 정지·시작·말 지시. 처음 한 번 PC 페이지에서 만든 연결 코드를 넣어야 합니다 (등록된 기기 0대)
```

처음 켤 때 **윈도우 방화벽이 파이썬의 네트워크 접근을 물어봅니다. 허용해야 폰이 닿습니다.**
네트워크가 "공용" 으로 잡혀 있으면 공용 쪽을 허용해야 합니다 (윈도우 설정에서 집 네트워크를
"개인" 으로 바꾸는 방법도 있습니다 — 어느 쪽이든 직접 정하세요).

### 연결 — 내 폰만

1. PC 페이지 뱀서 탭 → **폰으로 보기** → **연결 코드 만들기** → 6자리 숫자와 주소
2. 폰에서 주소를 열고 숫자 입력
3. 그 폰은 등록됩니다. 다음부터는 주소만 열면 됩니다 (브릿지를 다시 띄워도 기억합니다)

문단속:

| | |
|---|---|
| 코드 | 6자리, **2분 동안 한 번만**. 다섯 번 틀리면 무효 |
| 등록된 기기 | 쿠키로 알아봄 (`HttpOnly`, `SameSite=Strict`). 파일(`bot/remote_devices.json`, 깃 제외)에는 쿠키가 아니라 **해시만** |
| 등록 안 된 기기 | 코드 넣는 화면만 보임. 상태·그림은 전부 401 |
| 폰 잃어버림 | **연결한 기기 모두 끊기** → 즉시 막힘 |
| 키 입력 | 폰은 키를 직접 못 보냄. 지시만 보내고, PC 탭이 처리해 허용된 키만 누름. 키를 누르는 WebSocket 은 지금처럼 이 PC 안(127.0.0.1)에서만 받음 |

시험한 것 (브릿지 안전모드, 폰 창구는 이 PC 안에서만 열어서): 등록 전 `/state`·그림 막힘,
코드 없이·틀린 코드·다섯 번 틀린 뒤 맞는 코드 전부 거부, 같은 코드 두 번째 사용 거부,
등록 뒤 상태·그림 받음, 파일에 쿠키 값 없음, 모두 끊기 뒤 다시 막힘, 브릿지 재시작 뒤에도 등록 유지.

### 폰에서 지시하기

밖에서 보다가 막혀 있으면 폰에서 시킵니다.

| 폰에서 | 무슨 일이 |
|---|---|
| **■ 정지** | **브릿지가 바로** 잡고 있던 키를 떼고, 그 뒤로 오는 키를 막습니다. PC 탭이 멈춰 있어도 먹습니다. PC 탭은 2초 안에 받아 조작을 끕니다 |
| **▶ 시작** | 막힘을 풀고 PC 탭이 조작을 다시 켭니다 (확인을 한 번 묻습니다) |
| **말로 지시** | "화면에 있는 초록 버튼 눌러", "일단 중단해" 같은 문장. PC 탭이 받아 LLM 에게 지금 화면(그림 + 화면 글자)과 함께 물어, 할 일 하나를 고르게 합니다 |

LLM 이 고를 수 있는 일은 다섯 가지뿐입니다: **정지 · 시작 · 화면의 버튼 고르기 · 키 하나 · 아무것도 안 함**.
실제로 누르는 건 코드가 합니다.

- 버튼을 고르면 메뉴와 같은 길로 갑니다 — 커서를 옮기고, 다시 읽어 커서가 그 버튼 위에 섰는지 확인하고,
  그때만 엔터. 못 가면 누르지 않습니다. "초록 버튼" 처럼 색이나 위치로 말해도 LLM 이 그림을 보고 이름을 찾습니다.
- 키는 목록 안의 것만(enter, space, WASD, 방향키). LLM 이 ESC 를 고르면 누르지 않습니다.
- 지시를 처리하는 동안 자동 조작은 쉽니다 (키가 섞이지 않게). 처리 중에 온 지시는 건너뜁니다.
- **1분 안에 PC 탭이 못 받아간 지시는 버립니다.** PC 가 잠깐 멈췄다 돌아왔을 때 한참 전의 "시작" 이
  실행되면 곤란해서입니다.
- PC 앞에서 **조작 시작**을 누르면 폰에서 걸어둔 정지도 풀립니다.

결과는 폰의 지시 칸과 로그에 나옵니다: `"초록 버튼 눌러" → "파워업" 에서 엔터 [시작에서 s]`.
폰에서 보낸 글자와 LLM 이 쓴 글자는 PC 로그에 넣기 전에 태그를 무력화합니다.

시험한 것 (가짜 LLM, 가짜 타이틀 화면 — 시작 / 파워업(초록) / 컬렉션 / 종료):

| 지시 | 결과 |
|---|---|
| 초록 버튼 눌러 | `s enter` — 파워업으로 옮겨 확인하고 엔터 |
| 일단 중단해 | 정지, 키 안 누름 |
| (LLM 이 ESC 를 고름) | 누르지 않음 |
| 상점 들어가 (화면에 없음) | 누르지 않고 "보이는 것: 시작, 파워업, 컬렉션, 종료" |
| 지금 몇 판째야? | 아무것도 안 함 |
| 처리 중에 또 지시 | 건너뜀 |

브릿지 쪽 (안전모드, 시험 전용 포트): 등록 안 된 기기의 지시 거부, 정지 중 PC 탭이 보낸 키 차단,
지시 한 번만 전달, 200자에서 자름, 61초 지난 "시작" 버림, PC 에서 조작 시작 → 정지 풀림.

**실제 LLM 으로는 아직 돌려보지 않았습니다.** "초록 버튼" 을 제대로 알아보는지는 gemma3 로 한 번 해봐야 합니다.

### 게임 페이지(8743)는 이제 이 PC 에서만

예전 도커 설정(`"8743:80"`)은 같은 와이파이의 누구나 게임 페이지를 열 수 있었습니다. 키는 못 누르지만
굳이 열어둘 이유가 없어서 `127.0.0.1` 에만 묶었습니다. 다음에 `start.ps1` 로 띄울 때 적용됩니다.

### 안 보일 때

- **"브릿지에 닿지 않습니다"** — 폰이 같은 와이파이인지, 방화벽을 허용했는지. VPN 프로그램(NordVPN 등)을
  켜둔 PC 는 설정에 따라 같은 와이파이 기기의 접속을 막을 수 있습니다 (로컬 네트워크 허용 관련 설정).
- **"PC 페이지 소식 없음"** — PC 에서 뱀서 탭이 열려 있고 브릿지에 붙어 있어야 합니다.
  **브릿지를 다시 띄웠으면 PC 페이지를 새로고침**하세요 (페이지는 스스로 다시 붙지 않습니다 —
  나중에 `--live` 로 띄운 브릿지에 알아서 붙어 키를 누르기 시작하면 곤란해서입니다).
- **폰 화면이 늦게 바뀜** — PC 탭이 가려지면 브라우저가 느려집니다. 게임 창과 나란히 두세요.

### 밖에서 보려면 (모바일 데이터)

`192.168.x.x` 는 **집 공유기 안에서만 통하는 주소**라, 모바일 데이터로는 아예 닿지 않습니다 (실제로 겪었다).
폰과 PC 를 하나의 사설망으로 묶어야 합니다. **Tailscale** 을 권합니다 — 개인은 무료, 내 계정에 로그인한
기기끼리만 이어지고, 오가는 게 암호화되며, 공유기 설정을 건드릴 게 없습니다.

1. **PC**: <https://tailscale.com/download> 에서 윈도우용 설치 → 로그인 (구글 계정 등)
2. **폰**: 앱스토어/플레이스토어에서 Tailscale 설치 → **같은 계정**으로 로그인 → 켜기
3. PC 에서 브릿지를 다시 띄운다 (`.\start.ps1 -Live -Remote`). 이제 이런 줄이 생긴다:

   ```
   폰으로 보기 : http://100.x.x.x:8745  ← 밖에서 (Tailscale 등 사설망)
                 http://192.168.219.100:8745  ← 집 와이파이
   ```

   PC 페이지의 **폰으로 보기** 에도 같은 주소가 뜬다. 안 보이면 Tailscale 앱에 나오는 PC 의 `100.` 주소를 쓰면 된다.
4. 폰에서 Tailscale 을 켠 채로 `http://100.x.x.x:8745` 를 열고, PC 에서 만든 연결 코드를 넣는다.
   집 와이파이 주소로 이미 등록했어도 **이 주소로는 한 번 더** 넣어야 한다 (브라우저가 쿠키를 주소마다 따로 둔다).
   나가기 전에 집에서 Tailscale 주소로 미리 등록해두면 밖에서는 열기만 하면 된다.

안 열리면:

- **윈도우 방화벽** — Tailscale 네트워크도 공용/개인 중 하나로 잡힙니다. 브릿지(파이썬)를 그쪽에서도 허용해야 합니다.
- **NordVPN** — 같은 방식(WireGuard)으로 망을 만들어서 켜져 있으면 Tailscale 을 방해할 수 있습니다.
  안 되면 PC 에서 NordVPN 을 끄고 다시 해보세요.
- NordVPN 메시넷도 같은 역할을 하지만, 2025년에 종료 예고가 나왔다가 번복된 적이 있어서 지금 쓸 수 있는지는
  앱에서 확인해야 합니다. 쓸 수 있으면 메시넷 주소로 열면 됩니다 (역시 `100.` 으로 시작).

**공유기 포트포워딩으로 인터넷에 여는 건 권하지 않습니다** — 이 창구는 암호화(HTTPS)가 없어서 쿠키가 그대로
오가고, 이제 정지·시작·지시까지 받습니다. 특정 망에서만 받게 하려면 `--remote-host <그 망의 PC 주소>`
(예: Tailscale 주소만 받기 `--remote-host 100.x.x.x`).

## 화면 글자 읽기 (OCR)

시작 버튼과 레벨업 카드를 제대로 못 알아보는 문제가 있었습니다. 둘 다 결국 **글자를 읽는 문제**라,
윈도우에 들어 있는 글자 인식(`Windows.Media.Ocr`)을 붙였습니다.

- **설치할 것이 없습니다.** 브릿지가 PowerShell 로 `bot/ocr.ps1` 을 한 번 띄워두고 씁니다.
  이 PC 에는 한국어·영어 인식이 들어 있습니다.
- **빠릅니다.** 한 장에 0.02~0.16초 (LLM 은 몇 초).
- **없는 글자를 지어내지 않습니다.** 못 읽으면 빈칸입니다. LLM 이 "마나의 노래" 를 "슈퍼 소울" 로
  읽었던 것 같은 일이 없습니다.

**브릿지를 새로 띄워야** 씁니다. 뜰 때 이 줄이 나오면 준비된 것입니다:

```
OCR         : 윈도우 내장 글자 인식 준비됨 (ko)
```

예전 브릿지에 붙어 있으면 로그에 "글자 읽기(OCR) 실패" 가 한 번 뜨고, 그동안은 예전처럼 LLM 만 씁니다.

### 어디에 쓰나

| 자리 | 하는 일 |
|---|---|
| 화면 판별 | 아래 글자가 보이면 LLM 에게 묻기 전에 그 화면으로 봅니다. 한 번 알아본 화면은 기억합니다 |
| 타이틀 화면 | 가운데에 큰 파란 판이 없어서 "플레이 중" 으로 보일 수 있었습니다. 그러면 몰리가 시작 버튼 앞에서 WASD 만 누릅니다. 이제 카메라가 1초 넘게 멈춰 있으면 글자를 확인해서 `시작` 이 보이면 메뉴로 봅니다 |
| 메뉴 | 읽은 글자를 LLM 에게 같이 주고 "버튼은 전부 항목에 넣으라" 고 합니다. 시작 버튼을 빠뜨리지 않게 |
| 레벨업 | LLM 이 읽은 카드 이름이 화면 글자에 실제로 있는지 맞춰봅니다. 전부 있으면 **두 번 읽지 않고** 바로 고릅니다. 하나라도 없으면 예전처럼 두 번 읽어 대조합니다 |

LLM 이 읽은 이름을 OCR 글자로 바꿔치기하지는 않습니다. OCR 이 이름 옆 글자까지 한 줄로 붙여
읽을 수 있어서(`마늘 새로운!`), 확인하는 데만 씁니다.

### 글자로 화면 알아보기

`LLM` 메뉴의 **글자로 화면 알아보기** 칸에서 고칠 수 있습니다. 한 줄에 한 화면, 위에 있는 줄부터 봅니다:

```
levelup: 레벨 업, LEVEL UP
revive: 부활, REVIVE
chest: 보물, TREASURE
dead: 게임 오버, GAME OVER, 결과, RESULTS, 생존 시간
menu: 시작, START, 캐릭터 선택, 스테이지, STAGE, 파워업, POWER UP, 컬렉션, COLLECTION
```

띄어쓰기·대소문자는 무시하고(`컬렉 션` = `컬렉션`), 조금 틀려도 맞춥니다(`LEV6L UP!` = `LEVEL UP`).
`시작` 같은 흔한 글자는 결과 화면(`다시 시작`)에도 나올 수 있어 메뉴를 맨 아래에 뒀습니다.
직접 만든 화면 종류(예: `stage_select: 스테이지 선택`)도 됩니다.

### 확인하는 법

- `LLM → 지금 화면 글자 읽기` — 지금 화면에서 무슨 글자를 읽었고 무슨 화면으로 보는지 나옵니다.
- 게임 화면 위에 읽은 글자가 **하늘색 상자**로 잠깐 보입니다. `몰리 시야` 아래에도 한 줄 나옵니다.
- `레벨업 읽은 것 → 사진으로 시험` 에 **아무 화면이나** 넣으면 글자부터 읽고 무슨 화면인지 알려줍니다.
  레벨업이 아니면 거기서 멈춥니다. 레벨업 기록에는 `화면 글자(OCR): …` 가 같이 남습니다.

### 재본 것

작은 글씨는 원래 크기로는 놓쳐서 **2배로 키워** 보냅니다. 3배는 오히려 나빴습니다.

| 합성 화면 | 1배 | 2배 |
|---|---|---|
| 타이틀 `시작 / 파워업 / 컬렉션` | 컬렉션 놓침 | 전부 |
| 레벨업 카드 이름 4개 | 전부 정확 | 전부 정확 |
| 레벨업 버튼 `새로고침 / 건너뛰기 / 삭제` | 둘 놓치고 하나 틀림 | 전부 (조금씩 틀림) |
| 카드 설명 (작은 글씨) | 많이 틀림 | 대부분 맞음 |

가짜 LLM 으로 돌려본 레벨업 흐름:

| 경우 | LLM 호출 | 결과 |
|---|---|---|
| 제대로 읽음, OCR 로 전부 확인 | 읽기 → 고르기 | 두 번째 읽기를 건너뜀 |
| 이름을 지어냄 (`슈퍼 소울`) | 읽기 → 읽기 | 누르지 않음 |
| OCR 이 이름 하나를 놓침 | 읽기 → 읽기 → 고르기 | 예전처럼 두 번 읽어 확인 |
| OCR 을 못 씀 | 읽기 → 읽기 → 고르기 | 예전과 같음 |

실제 뱀서 화면으로는 아직 재보지 않았습니다. 뱀서 글씨체로 얼마나 읽는지는 **사진으로 시험**에
캡처를 넣어보면 바로 나옵니다.

## 게임 중인지 — 파란 창으로 판단

뱀서의 창(레벨업·일시정지·캐릭터 선택·결과)은 모두 **넓은 파란 판**입니다.
확인 영역에 파란 판이 기준 이상 보이면 **게임 아님**, 아니면 **플레이 중**으로 봅니다.

### 왜 바꿨나 — 판이 시작돼도 플레이를 못 알아봤습니다

예전에는 움직임만 봤습니다. "카메라도 안 움직이고 바깥 전장도 0.5초 이상 안 움직이면 멈춘 화면".
그런데 판이 막 시작하면 적도 거의 없고 캐릭터도 가만히 있습니다. 그러면:

1. 아무것도 안 움직이니 → 멈춘 화면으로 판단
2. 멈춘 화면이라 몰리가 키를 놓음
3. 키를 안 누르니 카메라가 안 움직임 → 계속 멈춘 화면

이렇게 **스스로 빠져나올 수 없는 고리**였습니다. 이제는 파란 창이 없으면 아무것도 안 움직여도
플레이 중이라 몰리가 키를 누르고, 카메라가 움직이기 시작합니다.

같이 고친 것: 화면이 **완전히 똑같은 프레임**으로만 들어오면(진짜로 멈춘 화면) 카메라 이동량이
마지막으로 잰 값에 멈춰 있었습니다. 마지막에 움직이고 있었다면 멈춘 화면이 영원히
"카메라 움직이는 중" 으로 남았습니다. 이제 0.3초 이상 같은 프레임이면 카메라도 멈춘 것으로 봅니다.

### 어디를, 무엇을 보나

- **확인 영역**: 레벨업 영역을 지정했으면 그 안, 아니면 게임 화면 가운데 (가로 20~80%, 세로 15~90%).
  맨 위 경험치 바도 파랗기 때문에 가장자리는 뺍니다. 게임 화면 위에 **파란 점선**으로 보입니다.
- **파란 판**: 확인 영역을 8×8 칸으로 나눠, 칸의 절반 이상이 파란 칸의 비율.
  파란 젬은 점처럼 작아서 칸을 채우지 못합니다.
- **빨강**: 참고로만 보여줍니다. 플레이 중에도 캐릭터 밑 체력바가 빨개서 이걸로는 가를 수 없습니다.

### 파란 바닥이 있는 맵

바닥이 파란 맵에서는 바닥을 창으로 착각했습니다. 그래서 파랗기만 해서는 창으로 보지 않고
세 가지를 더 봅니다.

1. **카메라가 움직이면 창이 아닙니다.** 창이 떠 있으면 게임이 멈추니 카메라도 멈춥니다.
   카메라가 0.4초 이상 멈춰 있어야 창일 수 있습니다. 몰리가 걷는 동안에는 이것만으로 충분합니다.
2. **무늬가 있으면 창이 아닙니다.** 창은 한 색으로 칠한 판이고, 바닥은 무늬가 있습니다.
3. **창 색을 기억합니다.** 레벨업 창을 한 번 제대로 읽으면 그 창의 바탕색을 기억하고,
   그다음부터는 그 색에 가까운 판만 창으로 봅니다. 무늬 없이 평평한 파란 바닥도 색이 다르면 빠집니다.
   자동으로 못 배웠으면 레벨업 창이 떠 있을 때 `민감도 → 지금 보이는 창 색 기억` 을 누르면 됩니다.

배울 때는 **파란 판만** 봅니다. 처음에는 가리지 않았더니, 테스트 영상에서 창 뒤에 어둡게 깔린
배경이 창보다 넓어서 그 배경색을 배웠습니다. 결과가 우연히 맞아 보여서 놓칠 뻔했습니다.

| 화면 | 창 색 모를 때 | 창 색 기억한 뒤 |
|---|---|---|
| 무늬 있는 파란 바닥 | 0% | 0% |
| 평평한 파란 바닥 — 걷는 중 | 96% → 카메라가 움직여 **게임 중** | 0% |
| 평평한 파란 바닥 — 멈춰 섬 | 96% → **창으로 착각** | **0%** |
| 레벨업 창 | 51% | 51% |
| 파란 바닥 맵 위의 레벨업 창 | 77% | 48% |

평평한 파란 바닥에 멈춰 서 있는 경우만 색을 배우기 전까지 막을 수 없습니다. 레벨업을 한 번
넘기면 풀립니다. `몰리 시야` 맨 아래에 `창이 아닌 파랑(바닥으로 보고 뺌) N%`, `창 색 기억함/모름`,
`카메라 멈춤/움직임` 이 같이 나오니, 착각하면 무엇 때문인지 바로 보입니다.

합성 화면으로 재본 값:

| 화면 | 파란 창 |
|---|---|
| 플레이 (젬 300개 + 경험치 바 + 체력바) | 0.1% |
| 후반 — 젬 1500개가 깔림 | 5.6% |
| 레벨업 창 (가운데를 볼 때) | 53% |
| 레벨업 창 (레벨업 영역을 지정했을 때) | 95% |
| 캐릭터 선택 | 50% |
| 어두운 남색 창 | 59% |

테스트 영상에서는 창이 뜨고 **0.3초** 뒤에 `예 (파란 창)`, 창이 닫히면 바로 `아니오`.
그리고 가만히 있는 플레이 화면을 넣었을 때, 예전 방식은 1.2초 만에 멈춘 화면으로 바꿨지만
지금은 플레이 중으로 유지합니다.

### 창 없이 멈추는 화면

보상 상자·게임 오버처럼 파란 판이 작거나 없는 화면도 있습니다. 그래서 파란 창이 없어도
**3초 동안 아무것도 안 움직이면** 그때는 멈춘 화면으로 봅니다. 플레이 중이라면 3초 동안
몰리가 키를 누르고 있으니 카메라가 움직여서 여기에 걸리지 않습니다.

### 설정 (`민감도` 메뉴)

- **파란 창이 보이면 게임 아님** — 끄면 예전처럼 움직임만 봅니다.
- **지금 보이는 창 색 기억 / 창 색 잊기** — 기억한 색은 견본으로 옆에 보입니다.
- **파란 창 기준** (기본 15%) — `몰리 시야` 맨 아래에 지금 값이 나옵니다:

  ```
  게임 멈춤: 예 (파란 창) — 파란 창 44% (15% 넘으면 게임 아님) · 빨강 3.6% · ...
  ```

  창이 떴을 때 값과 플레이 중 값 사이로 맞추면 됩니다. 물이 넓은 스테이지처럼 바닥이 파란 곳에서
  플레이 중인데 값이 높게 나오면 기준을 올리거나, 레벨업 영역을 지정해 확인 영역을 좁히세요.

## 레벨업 화면을 알아보는 과정

레벨업을 알아보는 건 한 번에 되는 게 아니라 여러 단계입니다. 단계마다 보는 곳이 다릅니다.

| 단계 | 보는 곳 | 하는 일 |
|---|---|---|
| ① 가르쳐준 화면인가 | 게임 영역 전체 (16×10 점) | 가르쳐준 화면과 차이 0.075 미만이면 그 화면 |
| ② 게임이 멈췄나 | **파란 창** (레벨업 영역 또는 가운데) | 파란 창이 보이면 멈춘 화면. 창 없이 3초 동안 아무것도 안 움직일 때도 멈춘 화면 (아래 참고) |
| ③ 모르는 화면일 때 | — | 멈췄으면 "멈춘 화면(종류 모름)", 아니면 플레이 중 |
| ④ LLM에게 묻기 | 게임 영역 전체 | ②가 참이고 ①에 없으면 한 번 묻고 기억 |
| ⑤ 카드 읽기 | 카드 영역 또는 게임 영역 | 레벨업으로 확정된 뒤 |

### 예전에 레벨업을 못 알아본 이유

②를 **화면 전체의 변화량**으로 봤습니다. 그러면 레벨업 창이 반짝이는 것도 '움직임' 이 됩니다.
재보니 반짝임만으로 변화량이 0.6 — LLM 판별 기준(0.6 이하)에 딱 걸려서 ④가 발동하지 않거나
들쭉날쭉했고, 1.5 를 넘으면 레벨업 중인데 **'플레이 중'** 으로 판정되어 몰리가 계속 움직였습니다.
그리고 ③은 play/menu 둘 뿐이라, ④가 발동하지 않으면 **레벨업은 절대 나오지 않았습니다.**

(①의 16×10 점은 의심했지만 원인이 아니었습니다. 같은 레벨업 화면 40쌍을 비교하면
차이가 평균 0.006 으로, 기준 0.075 에 한참 못 미칩니다.)

지금은 ②를 **가운데를 뺀 바깥 전장**으로 봅니다. 레벨업 창·메뉴는 가운데에 뜨고 그 뒤 전장은
멈추니까요. 카메라 보정 움직임(앞의 몬스터 판별과 같은 것)을 써서, 카메라가 안 움직이고
바깥 전장에서 스스로 움직이는 게 0.3% 미만이면 멈춘 것으로 봅니다.

테스트 영상에 **가운데에서 반짝이는 레벨업 창**을 띄워 확인했습니다:

| 상태 | 게임 멈춤 판정 | 바깥 전장 움직임 |
|---|---|---|
| 움직이는 중 | 아니오 8/8 | 0.26 ~ 1.06% |
| 레벨업처럼 멈춤 (창 반짝임) | **예 8/8** | 0.00 ~ 0.04% |
| 다시 움직임 | 아니오 8/8 | 0.31 ~ 0.88% |

`몰리 시야` 메뉴의 **테스트 영상 멈추기 (레벨업처럼)** 버튼으로 직접 볼 수 있습니다.

### 그래도 "무엇이 멈췄는지" 는 LLM 이 알려줘야 합니다

②는 "멈췄다" 까지만 압니다. 그게 레벨업인지 메뉴인지는 ①(가르쳐준 화면) 이나
④(LLM 판별) 가 알려줘야 합니다. 둘 다 없으면 상태가 **"멈춘 화면 (종류 모름)"** 으로 뜨고,
로그에 이렇게 알려줍니다:

```
게임이 멈췄는데 무슨 화면인지 모릅니다 — 가르쳐준 화면과 안 맞고, LLM 화면 판별도
꺼져 있어서 레벨업인지 알 수단이 없습니다.
```

`LLM → 화면 종류도 LLM이 판별` 을 켜두면 처음 보는 레벨업 화면에서 한 번 묻고 기억해서,
다음부터는 ①에서 바로 알아봅니다.

## 화면 전체를 봅니다

예전에는 **화면 높이를 지름으로 하는 원** 안만 봤습니다(`maxR = min(가로, 세로) / 2`).
16:9 화면에서는 넓이의 44% 뿐이고, 좌우 20% 씩은 **아예 안 봤습니다.**

```
가로를 10칸으로 나눠서 칸마다 보는 비율
예전:   0%   0%  38%  83%  98%  98%  84%  41%   0%   0%
지금: 100% 100% 100% 100%  96%  97% 100% 100% 100% 100%
```

뱀서는 몬스터가 **화면 밖에서 생겨 걸어 들어옵니다.** 좌우 끝이 몬스터가 처음 보이는 자리인데,
거기를 못 봐서 가까이 와서야 반응했습니다.

지금은 24x24 격자가 화면 사각형 전체를 덮습니다. 다만 **거리는 실제 픽셀 거리로** 잽니다 —
칸 좌표로 재면 가로가 더 길어서 옆에 있는 적이 실제보다 가깝게 계산됩니다.
거리 단위는 예전과 같은 "화면 높이의 절반" 이라서 이미 맞춰둔 값들이 그대로 통하고,
좌우 끝은 약 1.7 (위아래 끝의 1.78배 — 화면 비율과 같음)이 됩니다. 멀리 있으니 위협도 작게 잡힙니다.

가운데 **캐릭터 자리 4칸은 뺍니다.** 예전 기준은 칸 가운데보다 작아서 실제로는 한 칸도
빠지지 않았는데, 움직임으로 적을 가르면 캐릭터의 걷는 모션이 "움직이는 것" 으로 잡혀
자기 자신을 적으로 보게 되기 때문입니다.

게임 영역을 16:9 가 아닌 비율로 지정하면 그 비율에 맞춰 격자를 다시 만듭니다.
바꾼 뒤에도 반응 검사는 8/8 그대로입니다.

## 몬스터는 움직이는 것, 보석은 가만히 있는 것

예전에는 **배경보다 어두운 픽셀**을 적으로 셌습니다. 그래서 메뉴 화면에서도 어두운 곳이 적으로
잡혀 227마리가 나오곤 했습니다. 지금은 **움직임**으로 가릅니다 — 몬스터는 스스로 움직이고,
보석은 바닥에 붙어 있으니까요.

그대로 하면 안 되는 이유가 하나 있습니다. **카메라가 캐릭터를 따라다니므로, 캐릭터가 움직이면
바닥과 보석까지 화면 전체가 같이 밀립니다.** 프레임 차이만 보면 전부 움직이는 것으로 잡힙니다.

그래서 먼저 **화면 전체가 얼마나 밀렸나** 를 잽니다. 이전 프레임을 몇 칸씩 옮겨가며 가장 잘
겹치는 이동량을 찾고(가장자리의 HUD 는 카메라와 같이 안 움직이므로 안쪽만 봅니다), 그걸 빼고도
여전히 달라지는 곳만 몬스터로 봅니다.

| | 화면 중 '움직임' 으로 잡힌 비율 |
|---|---|
| 카메라 이동을 안 빼면 | **27%** — 바닥까지 전부 적 |
| 카메라 이동을 빼면 | **2.9%** — 몬스터만 |

합성 화면으로 검증한 결과: 카메라 이동 5가지를 전부 정확히 맞히고, 몬스터 8/8 을 잡고,
보석은 0개를 잘못 잡았습니다. 멈춘 화면에서는 움직이는 점이 0개 — 메뉴에서 적 0마리입니다.

### 같은 프레임이 두 번 들어올 때

분석은 66ms 마다 도는데 영상이 매번 새 장을 주지는 않습니다. 같은 장끼리 비교하면 아무것도
안 움직인 것으로 나와서 **적이 순간적으로 0마리** 가 됐습니다. 그렇다고 "같으면 직전 결과를 쓴다"
로만 하면 메뉴처럼 정말 멈춘 화면에서도 마지막 전투의 적이 남습니다. 픽셀로는 못 가르므로
**시간으로** 가릅니다 — 300ms 미만으로 같으면 영상이 늦은 것, 그보다 오래면 정말 멈춘 것.
고친 뒤 30번 재서 0으로 떨어진 횟수 0번입니다.

### 설정

`민감도` 메뉴의 **적 판별** 에서 고릅니다:

- **움직임** (기본) — 스스로 움직이는 것
- **색 + 움직임** — 어둡고 움직이는 것. 무기 이펙트가 적으로 잡히면 이쪽이 낫습니다
- **색** — 예전 방식

첫 프레임이나 장면이 확 바뀌어 카메라 이동을 못 잰 프레임은 자동으로 색으로 대신합니다.
무엇으로 판단했는지, 카메라가 얼마나 움직였는지는 `몰리 시야` 아래 줄에 나옵니다:

```
적 판별: 움직임 · 카메라 이동 (2, 0) · 정렬 오차 1.3 · 스스로 움직이는 점 291
```

알려진 한계: **무기 이펙트도 스스로 움직입니다.** 채찍·마법봉 같은 것이 적으로 잡힐 수 있습니다.
그럴 땐 `색 + 움직임` 으로 바꾸거나 움직임 민감도를 올리세요.

### 테스트 영상도 게임처럼 바꿨습니다

예전 테스트 영상은 배경이 단색이고 보석도 떠다녀서 이 방식을 시험할 수 없었습니다.
지금은 바닥 무늬가 스크롤되고(카메라가 따라감), 보석은 바닥에 붙어 있고, 몬스터만 캐릭터를
쫓아옵니다. 위쪽 HUD 는 화면에 고정입니다.

## 몰리 시야 — 뇌가 실제로 받는 것

게임 화면의 점(인식 표시)은 "무엇을 적으로 셌나" 까지만 보여줍니다. 그다음 — 24x24 격자로 줄이고,
8방향 위협·탈출·젬으로 요약하고, 방향마다 점수를 매겨 하나를 고르는 과정 — 은 보이지 않았습니다.

`몰리 시야` 메뉴에서 그걸 다 보여줍니다:

- **왼쪽**: 뇌가 받는 24x24 격자 (빨강 = 적, 파랑 = 젬). 몰리는 화면 픽셀이 아니라 이것만 봅니다
- **오른쪽**: 8방향 점수. 노란 굵은 선 = 시야로 고를 방향, 바깥 빨간 호 = 위협, 점선 = 실제로 누른 방향
  (초록이면 시야대로, 빨강이면 블라인드)
- **아래 표**: 방향마다 위협 · 탈출여지 · 젬 · 최종점수를 숫자로

```
시야로 고를 방향: 아래 (탈출여지 1.00 · 위협 0.00 · 젬 0.66) · 가장 위험한 쪽은 왼 (위협 1.00)
```

이 칸이 열려 있을 때만 그리므로 평소에는 부담이 없습니다. 테스트 영상으로도 볼 수 있습니다.

## 키를 보낼 창을 정해두세요

지금까지는 **활성 창이 무엇이든 그냥 키가 나갔습니다.** 알트탭으로 다른 프로그램에 가 있으면
거기에 대고 WASD를 칩니다. 창 제목을 확인해서 그 창이 앞에 있을 때만 보내게 했습니다.

페이지 위쪽 `대상 창` 칸에 제목 일부를 적으면 됩니다 (대소문자 구분 없음).
게임 창을 클릭해 앞으로 보낸 뒤 `지금 활성 창 넣기` 를 누르면 알아서 채워집니다.
브릿지를 다시 띄우지 않아도 바로 적용되고, 브릿지가 재시작되면 페이지가 다시 알려줍니다.

명령줄로 고정할 수도 있습니다:

```
bot\.venv\Scripts\python.exe bot\bridge.py --live --window "Vampire Survivors"
```

지정한 창이 아닐 때는 **잡고 있던 키까지 놓습니다.** 안 놓으면 알트탭한 순간
다른 창에 키가 눌린 채로 남습니다. 막혔다는 사실은 3초에 한 번만 로그에 찍습니다.

```
[창] 이제 'Vampire Survivors' 창이 활성일 때만 키를 보냅니다
[차단] 활성 창이 'MapleStory' 이라 키를 보내지 않습니다
```

비워두면 예전처럼 아무 창에나 보냅니다. 페이지에 경고가 뜹니다.

## 안전장치

- **기본이 안전모드** — `--live` 없이는 키를 누르지 않습니다
- **대상 창 확인** — 지정한 창이 앞에 있을 때만 키가 나갑니다. 아니면 잡고 있던 키까지 놓습니다
- **키 화이트리스트** — WASD/방향키/엔터/스페이스만 허용. ESC와 그 외 모든 키는 무시합니다
- **워치독** — 0.5초 동안 명령이 끊기면 눌린 키를 전부 놓습니다 (탭이 죽어도 키가 눌린 채 남지 않음)
- **Origin 검사** — 로컬에 열린 WebSocket은 아무 웹페이지나 접속할 수 있어서, 우리 페이지에서 온 연결만 받습니다
